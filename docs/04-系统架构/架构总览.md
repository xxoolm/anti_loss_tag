## 二、核心模块说明

### 2.1 Config Flow（配置流程）

**文件**：`config_flow.py`

**职责**：
- 引导用户完成设备添加
- 扫描并列出可用设备
- 创建配置条目（ConfigEntry）

**关键流程**：
```
用户触发
  ↓
显示配置表单
  ↓
扫描设备（5秒，ffe0过滤）
  ↓
用户选择设备
  ↓
创建配置条目
  ↓
触发设备添加
```

**技术要点**：
- 继承 `config_entries.ConfigFlow`
- 设置 `VERSION = 1`
- 实现 `async_step_user` 和 `async_step_bluetooth`
- 使用 `vol.Schema` 定义验证规则

---

### 2.2 Coordinator（协调器）

**文件**：`__init__.py`

**职责**：
- 集成的生命周期管理（`async_setup_entry`/`async_unload_entry`）
- 全局状态管理
- 事件路由和分发

**关键方法**：
- `async_setup_entry`：初始化集成，加载配置，创建设备
- `async_unload_entry`：清理资源，断开连接
- `async_handle_event`：处理设备事件（按钮、连接、断开）

**技术要点**：
- 使用 `hass.data` 存储设备实例
- 使用 `async_forward_entry_setups` 设置平台
- 实现正确的资源清理

---

### 2.3 BLE Device Manager（设备管理器）

**文件**：`device_manager.py`

**职责**：
- 维护全局设备注册表（MAC地址→设备实例）
- 扫描管理（短时扫描、UUID过滤）
- 连接管理（避免重复连接）
- 重连管理（指数退避）

**数据结构**：
```python
device_map: dict[str, BLEDevice]        # MAC地址→设备实例
client_map: dict[str, BleakClient]      # MAC地址→GATT客户端
reconnect_tasks: dict[str, asyncio.Task] # MAC地址→重连任务
```

**连接数限制**（重要！）：
- **ESPHome代理槽位限制**：2-3个并发连接
- **设备管理上限**：建议不超过8个设备
- **全局并发连接**：受蓝牙控制器硬件限制

**说明**：
- "3个并发连接" = 同时可以进行的GATT操作数
- "8个设备" = 可以管理的总设备数（包括未连接的）

---

### 2.4 BLE Device（单个设备）

**文件**：`device.py`

**职责**：
- 设备状态机（Disconnected/Connecting/Connected/Alarming）
- GATT 操作封装（连接、断开、读写特征值）
- 特征值管理（ffe1/ffe2/2a06/2a19）
- 数据解析（电量、按钮事件、RSSI）

**状态机**：
```
Disconnected（未连接）
    ↓ (用户触发/自动重连)
Connecting（连接中）
    ↓ (连接成功)
Connected（已连接）
    ↓ (检测到断开)
Disconnected（未连接）→ 触发重连
```

**关键方法**：
- `async_connect`：连接设备，服务发现，开启通知
- `async_disconnect`：断开连接，清理资源
- `async_write_alarm_policy`：写入断开报警策略（ffe2）
- `async_trigger_alarm`：触发即时报警（2a06）
- `async_read_battery`：读取电量（2a19）
- `async_start_rssi_polling`：开始RSSI轮询

**技术要点**：
- 使用 `bleak-retry-connector` 建立连接
- 使用 `_gatt_lock` 保护GATT操作
- 使用 `_connect_lock` 保护连接操作
- 实现指数退避重连策略

---

### 2.5 Entities（实体层）

**文件**：`sensor.py`、`binary_sensor.py`、`button.py`

**职责**：
- 向 Home Assistant 暴露设备状态
- 提供自动化触发点

**实体类型**：

#### 1. Sensor（传感器）
- `sensor.{设备名}_battery_level`：电量百分比
- `sensor.{设备名}_rssi`：信号强度
- `sensor.{设备名}_last_seen`：最后连接时间

#### 2. Binary Sensor（二进制传感器）
- `binary_sensor.{设备名}_connected`：连接状态
- `binary_sensor.{设备名}_alarming`：报警状态

#### 3. Button（按钮）
- `button.{设备名}_trigger_alarm`：触发报警

#### 4. Event（事件）
- `anti_loss_tag_button_event`：按钮事件（修复：统一事件名称）

**技术要点**：
- 使用 `@property` 暴露状态
- 实现 `async_added_to_hass` 和 `async_will_remove_from_hass`
- 使用 `device_info` 关联到同一设备

## 三、数据流分析

### 3.1 设备添加流程

```
Config Flow（用户触发）
  ↓
扫描设备（Scanner）
  - 使用 ffe0 过滤
  - 扫描 5 秒后停止
  ↓
用户选择设备
  ↓
创建 ConfigEntry
  ↓
Coordinator.async_setup_entry
  ↓
BLEDeviceManager.async_add_device
  ↓
BLEDevice.async_connect
  - 建立连接
  - 服务发现
  - 开启通知（ffe1）
  - 读取电量（2a19）
  - 配置策略（ffe2）
  ↓
创建 Entities
  - Sensor（电量、RSSI）
  - BinarySensor（连接、报警）
  - Button（触发报警）
  ↓
设备就绪
```

### 3.2 按钮事件流程

```
设备按键
  ↓
FFE1 通知上报（7字节数据）
  ↓
BLEDevice._on_characteristic_changed
  - 解析数据（字节0：事件类型）
  - 0x01=单击, 0x02=双击, 0x03=长按
  ↓
Coordinator.async_handle_event
  ↓
HASS.bus.fire("anti_loss_tag_button_event")
  - 事件数据：{"event_type": "单击/双击/长按"}
  ↓
用户自动化触发
```

**修复说明**：
- **旧事件名称**：`anti_loss_tag_button_pressed`
- **新事件名称**：`anti_loss_tag_button_event`（统一命名）

### 3.3 断开报警流程

```
连接断开
  ↓
BLEDevice._on_disconnected
  ↓
检查 alarm_on_disconnect 开关
  ↓
检查勿扰条件（Wi-Fi/时间）
  ↓
满足条件 → BLEDevice.async_trigger_alarm
  - 写入 2a06 (0x01)
  - 设备报警
  ↓
启动重连任务
```

**降级策略**：
- 如果设备不支持 ffe2：不触发断开报警
- 如果设备不支持 2a06：无法触发报警

## 四、关键技术决策

### 4.1 为什么使用 `local_push` IoT 类别？

**理由**：
- 设备通过 ffe1 通知**主动推送**按钮事件
- 电量/RSSI 虽然需要轮询，但**核心事件是推送的**
- 符合"设备主动通知"的定义

**对比 `local_polling`**：
- `local_polling`：需要持续轮询才能获取状态（延迟高）
- `local_push`：设备主动通知，延迟低

### 4.2 为什么使用 `device` 集成类型？

**理由**：
- 每个防丢标签是**独立的设备**
- 不是集线器架构（如 Philips Hue）
- 符合"提供单个设备"的定义

### 4.3 为什么使用 `bluetooth_adapters` 依赖？

**理由**：
- 需要 **BLE 扫描功能**（发现设备）
- 需要 **RSSI 监控**（距离判断）
- 官方推荐的 BLE 集成最佳实践

## 五、并发模型

### 5.1 异步架构

整个集成基于 **asyncio**，所有阻塞操作都是异步的：
- BLE 连接/断开
- GATT 读写
- 扫描操作
- RSSI 轮询

### 5.2 锁机制

为了保护关键操作，使用了以下锁：
- `_gatt_lock`：保护 GATT 操作（避免并发写入）
- `_connect_lock`：保护连接/断开操作
- `_reconnect_lock`：保护重连逻辑

**注意事项**：
- 不要在持有锁时执行耗时操作
- 避免死锁（嵌套锁）
- 使用 `async with` 而不是 `await lock.acquire()`

### 5.3 连接槽位管理

**问题**：ESPHome代理只有2-3个并发连接槽位

**解决方案**：使用全局信号量限制并发
```python
from asyncio import Semaphore

class BleConnectionManager:
    def __init__(self):
        # 限制全局并发连接数
        self._connection_semaphore = Semaphore(3)
    
    async def acquire_slot(self):
        """获取连接槽位"""
        await self._connection_semaphore.acquire()
    
    def release_slot(self):
        """释放连接槽位"""
        self._connection_semaphore.release()
```

## 六、错误处理策略

### 6.1 连接失败

**策略**：指数退避重连
- 初始间隔：5秒
- 最大间隔：60秒
- 最大重试次数：无限（用户可配置）

**实现**：
```python
async def _reconnect_with_backoff(self):
    delay = 5  # 初始延迟5秒
    max_delay = 60  # 最大延迟60秒
    
    while self._should_reconnect:
        try:
            await self.async_connect()
            break  # 连接成功，退出重连
        except Exception as e:
            _LOGGER.error(f"连接失败: {e}")
            await asyncio.sleep(delay)
            delay = min(delay * 2, max_delay)  # 指数退避
```

### 6.2 GATT 操作失败

**策略**：
- **写入失败**：重试3次，仍失败则重新连接
- **读取失败**：延迟重试
- **特征值不存在**：记录日志，标记设备不支持该功能

**实现**：
```python
async def safe_write(self, char_uuid, data, max_retries=3):
    """安全的写入操作（带重试）"""
    for attempt in range(max_retries):
        try:
            await self._client.write_gatt_char(char_uuid, data)
            return True
        except Exception as e:
            if attempt == max_retries - 1:
                _LOGGER.error(f"写入失败（已重试{max_retries}次）: {e}")
                return False
            await asyncio.sleep(0.5 * (attempt + 1))  # 递增延迟
```

### 6.3 设备离线

**策略**：
- **自动重连**：检测到断开后立即启动重连
- **报警策略**：根据配置决定是否触发断开报警
- **状态同步**：更新所有实体状态为不可用

## 七、性能优化

### 7.1 连接池管理

- 每个 MAC 地址只维护一个 BleakClient
- 避免重复连接（检查 `is_connected`）
- 定期清理僵尸连接

### 7.2 扫描优化

- **短时扫描**：5秒后自动停止
- **UUID 过滤**：只扫描 ffe0 服务
- **延迟启动**：扫描前延迟200ms（等待蓝牙就绪）

### 7.3 资源管理

- **特征值缓存**：服务发现后缓存特征值引用
- **通知复用**：只开启一次 ffe1 通知
- **任务清理**：unload 时取消所有后台任务

## 八、版本演进

### v1.x → v2.0.0 主要变更

**稳定性增强**：
1. **每设备优先级操作队列**
   - 报警按钮、策略同步、电量读取统一入队
   - 单 worker 串行执行，避免并发写入冲突

2. **连接状态机细分**
   - `idle / scanning / connecting / discovering / ready / degraded / backoff`
   - 每个失败路径写入错误分类和错误类型

3. **连接槽位全局调度**
   - 通过 `BleConnectionManager` 控制并发连接上限
   - 输出 `acquire_total/timeout/error/average_wait_ms` 指标

4. **前后台优先级策略**
   - 前台报警操作优先
   - 后台电量轮询在拥塞时自动延后

**API 兼容性**：
- 修复 bleak >= 0.21.0 API 兼容性问题
- 所有 UUID 统一为全小写
- 统一事件名称为 `anti_loss_tag_button_event`

## 十、扩展性设计

### 10.1 支持新设备

添加新设备只需：
1. 确认设备 UUID（ffe0/ffe1/ffe2/2a06/2a19）
2. 调整数据解析逻辑（如果协议不同）
3. 添加配置选项（设备特定参数）

### 10.2 自定义功能

扩展点：
- **自定义数据解析**：重写 `parse_notification_data`
- **自定义报警策略**：重写 `check_disconnect_alarm`
- **自定义自动化**：监听 `anti_loss_tag_button_event` 事件
