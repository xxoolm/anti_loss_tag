## 一、UUID 总表

> **重要说明**：所有 UUID 必须使用**全小写**格式，符合开发规范要求。

| UUID（全小写）                      | 类型                               | 作用                                                         | 典型数据                     | 使用时机                |
| ----------------------------------- | ---------------------------------- | ------------------------------------------------------------ | ---------------------------- | ----------------------- |
| `0000ffe0-0000-1000-8000-00805f9b34fb` | 自定义 Service（厂商私有）          | **扫描过滤服务**：只扫描广播里声明了该服务的设备             | 无（扫描过滤不读写数据）       | 扫描阶段                |
| `0000ffe1-0000-1000-8000-00805f9b34fb` | 自定义 Characteristic              | **通知上报通道**：连接后开启通知，设备主动上报信息（按钮事件等） | 字节流（设备定义协议）        | 连接成功 + 发现服务后   |
| `0000ffe2-0000-1000-8000-00805f9b34fb` | 自定义 Characteristic              | **断开报警策略配置**：配置断开连接时是否触发报警（单功能）   | `0x01`=开启、`0x00`=关闭       | 发现服务后立即写        |
| `00002a06-0000-1000-8000-00805f9b34fb` | 标准 Characteristic（Alert Level） | **即时报警控制**：控制设备立即开始/停止报警                   | `0x00`=取消、`0x01`= Mild      | 需要立即控制报警时      |
| `00002a19-0000-1000-8000-00805f9b34fb` | 标准 Characteristic（Battery Level）| **电量读取**：读取设备电量百分比                            | 0-100（1字节）                | 发现服务后读取/定时读取 |

### UUID 使用规范

```python
# ✅ 正确：全小写
SERVICE_UUID = "0000ffe0-0000-1000-8000-00805f9b34fb"
CHAR_NOTIFY_FFE1 = "0000ffe1-0000-1000-8000-00805f9b34fb"

# ❌ 错误：混合大小写
SERVICE_UUID = "0000FFE0-0000-1000-8000-00805F9B34FB"  # 不要使用
```

## 二、核心操作指令

### 1) 即时报警控制（2a06）

**写入 UUID**：`00002a06-0000-1000-8000-00805f9b34fb`

**写入方法**：**必须使用 Write Without Response**（不支持带响应的写入）

> **为什么必须用 Write Without Response？**  
> 2a06 是 Bluetooth SIG 标准的 Immediate Alert Service 特征，根据规范，该特征**只支持不带响应的写入**。使用带响应的写入会导致设备无响应或写入失败。

**语义**：让设备"立刻进入报警状态"（响/震/闪）

**写入数据**（基于 Bluetooth SIG 官方规范 - Immediate Alert Service）：
- `0x00` = 取消报警（No Alert）
- `0x01` = 开始报警（Mild Alert）- 轻度提醒
- `0x02` = 高级别报警（High Alert）- 强烈提醒

**正确使用流程**：
1. 确保已连接到设备
2. 完成服务发现，获取 Alert Level 特征
3. **使用 Write Without Response 方法写入报警级别**
4. 设备立即响应并开始或停止报警
5. 报警持续直到：超时、用户交互、物理链路断开、或收到新的报警级别

**代码示例**（bleak >= 0.21.0）：
```python
from bleak import BleakClient

async def trigger_alarm(client: BleakClient, alert_level: int):
    """
    触发即时报警
    
    Args:
        client: BleakClient 实例（必须已连接）
        alert_level: 0x00=取消, 0x01=Mild, 0x02=High
    """
    char_uuid = "00002a06-0000-1000-8000-00805f9b34fb"
    data = bytes([alert_level])
    
    # ⚠️ 关键：response=False（不带响应的写入）
    await client.write_gatt_char(
        char_uuid, 
        data, 
        response=False  # 必须设置为 False
    )
```

**常见错误**：
- ❌ 使用 `response=True`：设备不会响应，写入会超时
- ❌ 未等待连接完成：必须在服务发现后才写入
- ❌ 字节格式错误：必须使用 `bytes([0x01])` 而不是 `0x01`

### 2) 断开报警策略配置（ffe2）

**写入 UUID**：`0000ffe2-0000-1000-8000-00805f9b34fb`

**语义**：配置"断开连接时是否触发报警"的策略开关

> **功能说明**：  
> ffe2 是**单一功能**的配置通道，专门用于"断开报警策略"。与某些文档描述的"多功能配置通道"不同，本项目仅使用其断开报警功能。

**写入数据**：
- `0x01`（true）= 开启断开报警
- `0x00`（false）= 关闭断开报警

**正确使用流程**：
1. 连接成功 + 服务发现完成
2. 在以下时机写入：
   - **连接刚建立时**：把本地设置同步给设备
   - **用户修改设置时**：立即更新设备端策略
3. 避免并发写入，等待回调后再发下一条

**代码示例**：
```python
async def set_alarm_policy(client: BleakClient, enabled: bool):
    """
    设置断开报警策略
    
    Args:
        client: BleakClient 实例（必须已连接）
        enabled: True=开启断开报警, False=关闭
    """
    char_uuid = "0000ffe2-0000-1000-8000-00805f9b34fb"
    data = bytes([0x01 if enabled else 0x00])
    
    # 等待写入回调确认
    await client.write_gatt_char(char_uuid, data)
```

**注意事项**：
- ⚠️ 写入 ffe2 后，设备会**记住这个策略**，直到下次修改
- ⚠️ 断开报警触发时，设备会自动使用 2a06 触发报警
- ⚠️ 如果关闭断开报警，连接断开后设备不会报警

### 3) 电量读取（2a19）

**读取 UUID**：`00002a19-0000-1000-8000-00805f9b34fb`

**语义**：读取设备当前电量百分比

**读取流程**：
1. 连接成功 + 服务发现完成
2. 发起读取请求
3. **等待读取回调**，解析数据（0-100百分比）
4. 存储并更新UI

**数据格式**：
- **长度**：1 字节
- **范围**：0-100（百分比）
- **示例**：`0x64` = 100%

**代码示例**（bleak >= 0.21.0）：
```python
from bleak import BleakClient

async def read_battery(client: BleakClient) -> int:
    """
    读取设备电量
    
    Returns:
        int: 电量百分比（0-100），如果读取失败返回 -1
    """
    char_uuid = "00002a19-0000-1000-8000-00805f9b34fb"
    
    try:
        # bleak >= 0.21.0: read_gatt_char 返回 bytes
        data = await client.read_gatt_char(char_uuid)
        
        if data and len(data) > 0:
            battery_level = data[0]
            # 验证范围
            if 0 <= battery_level <= 100:
                return battery_level
            else:
                # 超出范围，可能数据格式错误
                return -1
        else:
            return -1
    except Exception as e:
        _LOGGER.error(f"读取电量失败: {e}")
        return -1
```

**降级策略**：
- 如果设备不支持 2a19（读取失败或返回无效数据）：
  - 电量传感器显示"未知"
  - 不影响其他功能正常使用
  - 日志记录"设备不支持电量读取"

## 三、通知上报机制（ffe1）

**通知 UUID**：`0000ffe1-0000-1000-8000-00805f9b34fb`

**语义**：设备主动上报信息的通道（按钮事件、状态变化等）

### 启用流程

1. 连接成功 + 服务发现完成
2. 找到 ffe1 特征值
3. **开启通知**（start_notify）
4. 设备主动上报时触发回调函数

### 按钮事件数据格式

> **重要**：本项目明确定义了完整的按钮事件类型，解决了旧文档中的描述不一致问题。

**数据格式**（7字节）：
```
字节0: 事件类型
  - 0x01: 单击（快速按1次）
  - 0x02: 双击（快速按2次）
  - 0x03: 长按（按住2秒以上）
字节1-6: 保留（当前未使用，值为 0x00）
```

**示例数据**：
```python
# 单击事件
[0x01, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]

# 双击事件
[0x02, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]

# 长按事件
[0x03, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]
```

### 代码示例（bleak >= 0.21.0）

```python
from bleak import BleakClient
from bleak.exc import BleakError
import logging

_LOGGER = logging.getLogger(__name__)

class ButtonEventHandler:
    """按钮事件处理器"""
    
    def __init__(self, client: BleakClient):
        self.client = client
        self.notify_callback = None
    
    async def start_notify(self, callback):
        """
        开启 ffe1 通知
        
        Args:
            callback: 回调函数，接收 (data: bytes)
        """
        char_uuid = "0000ffe1-0000-1000-8000-00805f9b34fb"
        self.notify_callback = callback
        
        try:
            await self.client.start_notify(char_uuid, self._on_notification)
            _LOGGER.info("FFE1 通知已开启")
        except BleakError as e:
            _LOGGER.error(f"开启 FFE1 通知失败: {e}")
            raise
    
    async def _on_notification(self, sender: int, data: bytearray):
        """
        通知回调函数
        
        Args:
            sender: 特征句柄
            data: 接收到的数据（7字节）
        """
        try:
            if len(data) < 1:
                _LOGGER.warning("收到空的通知数据")
                return
            
            event_type = data[0]
            
            # 解析事件类型
            if event_type == 0x01:
                event_name = "单击"
            elif event_type == 0x02:
                event_name = "双击"
            elif event_type == 0x03:
                event_name = "长按"
            else:
                _LOGGER.warning(f"未知事件类型: 0x{event_type:02X}")
                return
            
            _LOGGER.info(f"收到按钮事件: {event_name}")
            
            # 调用用户回调
            if self.notify_callback:
                await self.notify_callback(event_name, bytes(data))
                
        except Exception as e:
            _LOGGER.error(f"处理通知失败: {e}")
```

### 注意事项

- ⚠️ 不同设备对"开启通知"的要求不同
- ⚠️ 有些设备需要写入 CCCD 描述符才能生效
- ⚠️ 建议在服务发现后立即开启通知
- ⚠️ 如果开启通知失败，按钮事件功能将不可用

## 四、BLE 通信最佳实践

### 1. 操作顺序（必须严格遵守）

> **重要**：错误的操作顺序会导致功能异常或设备无响应。

```python
# ✅ 正确的顺序（必须按此顺序执行）
async def connect_and_setup(device_address: str):
    """
    连接设备并完成初始化的完整流程
    """
    client = BleakClient(device_address)
    
    try:
        # 1. 连接
        await client.connect()
        
        # 2. 服务发现（bleak >= 0.21.0：services 是属性，不是方法）
        services = client.services  # ⚠️ 不要使用 await client.get_services()
        
        # 3. 开启通知（ffe1）- 必须在配置策略之前
        await start_notify(client, "0000ffe1-0000-1000-8000-00805f9b34fb")
        
        # 4. 读取电量（2a19）- 可选
        battery = await read_battery(client, "00002a19-0000-1000-8000-00805f9b34fb")
        
        # 5. 配置策略（ffe2）- 必须在开启通知之后
        await set_alarm_policy(client, "0000ffe2-0000-1000-8000-00805f9b34fb", True)
        
        # 6. 准备就绪
        _LOGGER.info("设备初始化完成")
        
    except Exception as e:
        _LOGGER.error(f"设备初始化失败: {e}")
        await client.disconnect()
```

**为什么必须按此顺序？**
1. **服务发现**必须在所有操作之前：需要获取特征值引用
2. **开启通知**必须在配置策略之前：否则可能错过早期的按钮事件
3. **配置策略**放在最后：确保设备状态完整后再设置策略

### 2. 并发控制

- **同一连接避免并发写入**：一次只发一条，等待回调后再发下一条
- **以回调 status 为准**：提交成功≠写入成功，必须等待回调确认

```python
# ❌ 错误：并发写入
await write_char1(client, data1)
await write_char2(client, data2)  # 可能与第一个冲突

# ✅ 正确：串行写入
await write_char1(client, data1)
await asyncio.sleep(0.1)  # 等待回调
await write_char2(client, data2)
```

### 3. 错误处理

| 错误类型           | 处理建议                                   | 降级策略                     |
| ------------------ | ------------------------------------------ | ---------------------------- |
| 连接失败           | 延迟重试，使用指数退避（5s→10s→20s→60s）  | 重试3次后放弃                |
| 服务发现失败       | 重新连接                                   | 标记设备不可用               |
| 写入失败           | 重试3次，仍失败则重新连接                   | 标记功能不可用               |
| 通知开启失败       | 检查设备是否支持，尝试写入 CCCD             | 禁用按钮事件功能             |
| 特征值不存在（2a19）| 记录日志，标记设备不支持该功能              | 电量显示"未知"               |
| 特征值不存在（ffe2）| 记录日志，不支持断开报警策略                | 禁用断开报警功能             |

### 4. 性能优化

- **短时扫描**：扫描 5 秒后自动停止，节省电量
- **UUID 过滤**：扫描时使用 ffe0 过滤，减少无关设备
- **特征缓存**：服务发现后缓存特征值引用，避免重复查询
- **连接池管理**：维护 MAC→Client 的映射，避免重复连接

## 五、功能降级矩阵

> **降级策略**：当某个功能不可用时，系统的应对方案。

| 功能    | 依赖的 UUID | 不可用时的表现              | 降级策略                     |
| ------- | ----------- | --------------------------- | ---------------------------- |
| 扫描    | ffe0        | 无法发现设备                | 无法使用（无降级）           |
| 按钮事件 | ffe1        | 无法接收按钮事件            | 禁用自动化，其他功能正常     |
| 断开报警 | ffe2        | 无法设置断开报警策略        | 禁用断开报警，其他功能正常   |
| 即时报警 | 2a06        | 无法触发报警                | 报警功能不可用               |
| 电量显示 | 2a19        | 无法读取电量                | 显示"未知"，其他功能正常     |

**示例代码**（功能降级）：
```python
class BLEDevice:
    def __init__(self):
        self.supports_battery = True
        self.supports_button = True
        self.supports_alarm_policy = True
    
    async def check_features(self, client: BleakClient):
        """检查设备支持的功能"""
        services = client.services
        
        # 检查 2a19（电量）
        if not self._get_char(services, "00002a19-0000-1000-8000-00805f9b34fb"):
            self.supports_battery = False
            _LOGGER.warning("设备不支持电量读取")
        
        # 检查 ffe1（按钮）
        if not self._get_char(services, "0000ffe1-0000-1000-8000-00805f9b34fb"):
            self.supports_button = False
            _LOGGER.warning("设备不支持按钮事件")
        
        # 检查 ffe2（断开报警策略）
        if not self._get_char(services, "0000ffe2-0000-1000-8000-00805f9b34fb"):
            self.supports_alarm_policy = False
            _LOGGER.warning("设备不支持断开报警策略")
```

## 六、数据格式完整定义

### 6.1 电量数据（2a19）

- **长度**：1 字节
- **范围**：0-100（百分比）
- **示例**：
  - `0x00` = 0%
  - `0x64` = 100%
  - `0x32` = 50%

### 6.2 按钮事件（ffe1 通知）

- **长度**：7 字节
- **格式**：
  ```
  字节0: 事件类型（0x01=单击, 0x02=双击, 0x03=长按）
  字节1-6: 保留（0x00）
  ```
- **示例**：
  - 单击：`[0x01, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]`
  - 双击：`[0x02, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]`
  - 长按：`[0x03, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]`

### 6.3 策略配置（ffe2 写入）

- **长度**：1 字节
- **值**：
  - `0x01` = 开启断开报警
  - `0x00` = 关闭断开报警

### 6.4 即时报警（2a06 写入）

- **长度**：1 字节
- **值**：
  - `0x00` = 取消报警
  - `0x01` = Mild Alert（轻度）
  - `0x02` = High Alert（强烈）

## 七、常见问题（FAQ）

### Q1: 为什么写入 2a06 后设备没有反应？

**A**: 检查以下几点：
1. ✅ 是否使用了 `response=False`？（必须用 Write Without Response）
2. ✅ 是否等待了写入回调？
3. ✅ 设备是否支持即时报警功能？
4. ✅ 电量是否充足？（低电量可能无法触发报警）

### Q2: 为什么收不到 ffe1 通知？

**A**: 检查以下几点：
1. ✅ 是否成功开启了通知（检查回调 status）？
2. ✅ 是否按正确的顺序操作（开启通知 → 配置策略）？
3. ✅ 部分设备需要写入 CCCD 描述符
4. ✅ 确认设备固件支持该功能

### Q3: 扫描为什么扫不到设备？

**A**: 检查以下几点：
1. ✅ 是否使用了 ffe0 服务 UUID 过滤？
2. ✅ 设备是否正在广播（有些设备有广播间隔）？
3. ✅ 蓝牙权限是否已授予？
4. ✅ 设备电量是否充足？

### Q4: 为什么电量读取返回 -1 或"未知"？

**A**: 可能的原因：
1. ❌ 设备不支持 2a19 特征
2. ❌ 连接不稳定，读取超时
3. ❌ 数据格式错误（不在 0-100 范围）

**降级策略**：电量显示"未知"，不影响其他功能使用

### Q5: UUID 大小写有区别吗？

**A**: **有区别！**
- ✅ **必须使用全小写**：`0000ffe0-0000-1000-8000-00805f9b34fb`
- ❌ **不要使用混合大小写**：`0000FFE0-0000-1000-8000-00805F9B34FB`

某些系统（特别是 Linux BlueZ）对 UUID 大小写敏感，使用错误的格式可能导致匹配失败。
