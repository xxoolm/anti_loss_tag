# 常见问题诊断

> **用户常见问题和解决方案**
> 
**目标读者**：普通用户  
**用途**：快速诊断和解决问题

## 🚨 快速诊断流程

遇到问题时，按以下顺序排查：

```
1. 检查设备状态
   ↓
2. 查看错误日志
   ↓
3. 对照问题列表
   ↓
4. 尝试解决方案
   ↓
5. 如仍未解决，查看诊断工具
```

## 一、安装和配置问题

### 问题1：安装后找不到集成

**症状**：
- 在"添加集成"中搜索不到"BLE 防丢标签"
- HACS 中下载后不显示

**可能原因**：
1. 未重启 Home Assistant
2. 文件路径不正确
3. manifest.json 格式错误
4. Python 依赖未安装

**解决方案**：

**步骤1：检查文件是否存在**
```bash
# SSH 到 Home Assistant
# 检查文件是否存在
ls ~/.homeassistant/custom_components/anti_loss_tag/

# 应该看到这些文件：
# __init__.py
# manifest.json
# config_flow.py
# ...
```

**步骤2：检查 manifest.json**
```bash
cat ~/.homeassistant/custom_components/anti_loss_tag/manifest.json
```

应该看到有效的 JSON，没有语法错误。

**步骤3：重启 Home Assistant**
```
设置 → 系统 → 服务器管理 → 重启
```

**步骤4：检查日志**
```
设置 → 系统 → 日志
搜索 "anti_loss_tag"
```

---

### 问题2：配置保存失败

**症状**：
- 点击"提交"后报错
- 配置没有保存

**可能原因**：
1. 设备已存在
2. MAC 地址格式错误
3. 配置参数验证失败

**解决方案**：

**步骤1：检查设备是否已配置**
```
设置 → 设备与服务 → BLE 防丢标签
```
查看是否已经有相同设备。

**步骤2：检查 MAC 地址格式**
```
✅ 正确格式：AA:BB:CC:DD:EE:FF
❌ 错误格式：AA-BB-CC-DD-EE-FF
❌ 错误格式：aabbccddeeff
```

**步骤3：查看日志中的错误信息**
```
设置 → 系统 → 日志
搜索 "anti_loss_tag" 或 "config_flow"
```

## 二、扫描和连接问题

### 问题3：扫描不到设备

**症状**：
- 配置时扫描列表为空
- 无法发现设备

**可能原因**：
1. 设备未开机
2. 设备距离太远
3. 蓝牙适配器未工作
4. 设备被其他设备连接

**解决方案**：

**步骤1：确认设备状态**
- ✅ 设备已开机（检查指示灯）
- ✅ 设备电量充足
- ✅ 设备未连接到其他设备（如手机）

**步骤2：靠近设备**
- 将设备靠近 Home Assistant（< 1米）
- 确保没有障碍物阻隔

**步骤3：检查蓝牙适配器**
```bash
# Linux
hciconfig -a

# 应该看到类似输出：
# hci0:	Type: Primary  Bus: USB
# 	BD Address: XX:XX:XX:XX:XX:XX  ACL MTU: 1021:8  SCO MTU: 64:1
# 	UP RUNNING 
# 	RX bytes:1234 acl:0 sco:0 events:123 errors:0
# 	TX bytes:5678 acl:0 sco:0 commands:123 errors:0
```

**步骤4：手动测试扫描**
```bash
# 使用 bluetoothctl
bluetoothctl
scan on
# 查看是否能扫描到设备
scan off
exit
```

**步骤5：查看日志**
```
设置 → 系统 → 日志
搜索 "bluetooth" 或 "scanner"
```

---

### 问题4：连接频繁断开

**症状**：
- 设备连接后很快断开
- 连接状态频繁切换

**可能原因**：
1. 蓝牙信号不稳定
2. 设备距离太远
3. 设备电量不足
4. 其他蓝牙设备干扰
5. 设备固件问题

**解决方案**：

**步骤1：检查信号强度**
```
设置 → 设备与服务 → BLE 防丢标签
查看 RSSI 传感器
```
- **RSSI < -80 dBm**：信号太差，需要靠近
- **RSSI > -60 dBm**：信号良好

**步骤2：靠近设备**
- 将设备靠近（< 5米）
- 移除障碍物
- 避免金属遮挡

**步骤3：检查设备电量**
- 如果电量 < 20%，请充电
- 低电量可能导致连接不稳定

**步骤4：检查干扰源**
- 微波炉
- 无线路由器（2.4GHz）
- 其他蓝牙设备
- 尽量远离这些设备

**步骤5：使用 ESPHome 代理**
- 如果距离较远，考虑使用 ESPHome 蓝牙代理
- 参考：[ESPHome 蓝牙代理](https://esphome.io/components/bluetooth_proxy.html)

**步骤6：调整配置**
```yaml
# 增加连接超时
connection_timeout_sec: 30

# 增加重连延迟
reconnect_delay_sec: 10
```

---

### 问题5：连接后立即断开

**症状**：
- 设备显示"已连接"
- 几秒后立即断开
- 循环重复

**可能原因**：
1. 设备被其他应用抢占
2. 蓝牙适配器驱动问题
3. 设备固件不兼容
4. 服务发现失败

**解决方案**：

**步骤1：检查设备是否被其他应用连接**
- 关闭手机上的蓝牙应用
- 确保设备只连接到 Home Assistant

**步骤2：查看详细日志**
```
设置 → 系统 → 日志
选择 "正确" 日志级别
搜索 "anti_loss_tag"
```

**步骤3：重启蓝牙适配器**
```bash
# Home Assistant OS
hassio hardware audio restart

# Linux
sudo systemctl restart bluetooth
```

**步骤4：更新设备固件**
- 联系设备供应商获取最新固件
- 按照设备说明更新固件

## 三、数据和事件问题

### 问题6：电量不更新

**症状**：
- 电量传感器一直显示相同值
- 电量显示"未知"

**可能原因**：
1. 轮询间隔太长
2. 设备不支持 2a19 特征
3. 设备未连接
4. 读取失败

**解决方案**：

**步骤1：检查设备连接状态**
```
设置 → 设备与服务 → BLE 防丢标签
查看"连接状态"二进制传感器
```
- 如果是"关"（未连接），电量不会更新

**步骤2：检查轮询间隔**
```
设置 → 设备与服务 → BLE 防丢标签 → 配置
查看"电量轮询间隔"
```
- 如果设置过长（如 1440 分钟），会很久才更新
- 建议设置为 360 分钟（6小时）

**步骤3：手动触发电量读取**
```
设置 → 设备与服务 → BLE 防丢标签
点击"重新加载"按钮
```

**步骤4：检查设备是否支持电量读取**
```bash
# 查看日志
设置 → 系统 → 日志
搜索 "2a19" 或 "battery"
```

如果看到"设备不支持电量读取"：
- 这是设备硬件限制
- 无法通过软件修复
- 电量传感器会显示"未知"

**步骤5：检查错误日志**
```
设置 → 系统 → 日志
搜索 "read_battery" 或 "gatt"
```

---

### 问题7：按钮事件不触发

**症状**：
- 按下设备按钮，Home Assistant 没有反应
- 自动化不执行

**可能原因**：
1. 通知未开启
2. 设备不支持 ffe1 特征
3. 事件订阅失败
4. 自动化配置错误

**解决方案**：

**步骤1：检查设备是否支持按钮事件**
- 确认设备规格支持按钮功能
- 查看 [协议规范](../05-协议规范/协议规范.md)

**步骤2：检查通知是否开启**
```bash
# 查看日志
设置 → 系统 → 日志
搜索 "ffe1" 或 "notify"
```

应该看到类似：
```
INFO:FFE1 通知已开启
```

如果看到"开启通知失败"：
- 设备可能不支持 ffe1 特征
- 这是设备硬件限制

**步骤3：测试事件是否触发**
```bash
# 查看日志
设置 → 系统 → 日志
搜索 "button" 或 "event"
```

按下设备按钮时，应该看到：
```
INFO:收到按钮事件: 单击
DEBUG:Firing event: anti_loss_tag_button_event
```

**步骤4：检查自动化配置**
```yaml
# 示例自动化
automation:
  - alias: "测试按钮事件"
    trigger:
      - platform: event
        event_type: anti_loss_tag_button_event
    action:
      - service: logger.log
        data:
          message: "按钮事件触发！"
```

**步骤5：使用事件监听器**
```
设置 → 开发者工具 → 事件
监听：anti_loss_tag_button_event
```

按下设备按钮，查看是否显示事件。

### 问题8：报警不响

**症状**：
- 触发报警后，设备没有反应
- 断开连接时不报警

**可能原因**：
1. 设备不支持 2a06 特征
2. 2a06 写入方式错误
3. 设备电量不足
4. 设备静音模式

**解决方案**：

**步骤1：手动测试报警**
```
设置 → 设备与服务 → BLE 防丢标签
点击"触发报警"按钮
```

**步骤2：检查设备是否支持报警**
```bash
# 查看日志
设置 → 系统 → 日志
搜索 "2a06" 或 "alarm"
```

如果看到"设备不支持即时报警"：
- 这是设备硬件限制
- 无法通过软件修复

**步骤3：检查设备电量**
- 设备电量过低可能无法触发报警
- 建议电量 > 20%

**步骤4：检查设备静音模式**
- 某些设备有静音开关
- 检查设备是否设置为静音

**步骤5：查看详细日志**
```bash
# 启用调试日志
# configuration.yaml
logger:
  default: info
  logs:
    custom_components.anti_loss_tag: debug
    bleak: debug
```

重启后查看日志。

## 四、性能和稳定性问题

### 问题9：Home Assistant 运行缓慢

**症状**：
- 添加多个设备后 HA 变慢
- CPU 使用率升高
- 日志中有大量错误

**可能原因**：
1. 连接数超过限制
2. 轮询频率太高
3. 蓝牙适配器性能不足
4. 并发连接冲突

**解决方案**：

**步骤1：检查设备数量**
- ESPHome 代理建议不超过 3-4 个设备
- USB 适配器建议不超过 5-8 个设备

**步骤2：调整轮询间隔**
```yaml
# 降低轮询频率
battery_poll_interval_min: 720  # 增加到12小时
rssi_poll_interval_min: 30      # 增加到30分钟
```

**步骤3：关闭维持连接**
```yaml
maintain_connection: false  # 关闭常驻连接
```

**步骤4：使用多个蓝牙适配器**
- 添加更多 USB 蓝牙适配器
- 或使用多个 ESPHome 代理
- 分散设备负载

**步骤5：检查资源使用**
```bash
# SSH 到 Home Assistant
top -bn1 | head -20
```

查看 CPU 和内存使用情况。

---

### 问题10：大量错误日志

**症状**：
- 日志中有大量重复错误
- 日志文件快速增长

**常见错误类型**：

**错误1：连接超时**
```
ERROR:连接超时: AA:BB:CC:DD:EE:FF
```

**解决方案**：
- 增加连接超时时间
- 检查蓝牙信号
- 靠近设备

**错误2：GATT 操作失败**
```
ERROR:写入失败: ...
ERROR:读取失败: ...
```

**解决方案**：
- 检查设备是否连接
- 查看设备是否支持该特征
- 增加重试延迟

**错误3：设备离线**
```
WARNING:设备离线: AA:BB:CC:DD:EE:FF
```

**解决方案**：
- 这是正常的，等待自动重连
- 如果长时间离线，检查设备状态
