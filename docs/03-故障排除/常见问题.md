```
1. 检查设备状态

   ↓
```

## 一、安装和配置问题

### 问题1：安装后找不到集成

**症状**：
- 在"添加集成"中搜索不到"BLE 防丢标签"
- HACS 中下载后不显示

**可能原因**：
1. 未重启 Home Assistant
2. 文件路径不正确
3. manifest.json 格式错误
4. Python 依赖未安装

**解决方案**：

**步骤1：检查文件是否存在**
```bash
# SSH 到 Home Assistant
# 检查文件是否存在
ls ~/.homeassistant/custom_components/anti_loss_tag/

# 应该看到这些文件：
# __init__.py
# manifest.json
# config_flow.py
# ...
```

**步骤2：检查 manifest.json**
```bash
cat ~/.homeassistant/custom_components/anti_loss_tag/manifest.json
```

应该看到有效的 JSON，没有语法错误。

**步骤3：重启 Home Assistant**
```
设置 → 系统 → 服务器管理 → 重启
```

**步骤4：检查日志**
```
设置 → 系统 → 日志
搜索 "anti_loss_tag"
```

---

### 问题2：配置保存失败

**症状**：
- 点击"提交"后报错
- 配置没有保存

**可能原因**：
1. 设备已存在
2. MAC 地址格式错误
3. 配置参数验证失败

**解决方案**：

**步骤1：检查设备是否已配置**
```
设置 → 设备与服务 → BLE 防丢标签
```
查看是否已经有相同设备。

**步骤2：检查 MAC 地址格式**
```
✅ 正确格式：AA:BB:CC:DD:EE:FF
❌ 错误格式：AA-BB-CC-DD-EE-FF
❌ 错误格式：aabbccddeeff
```

**步骤3：查看日志中的错误信息**
```
设置 → 系统 → 日志
搜索 "anti_loss_tag" 或 "config_flow"
```

### 问题2.5：没有可用的蓝牙适配器

**症状**：
- 添加集成时提示"蓝牙适配器未就绪"
- 日志显示"没有可用的扫描器"
- 设备列表为空

**可能原因**：
1. 蓝牙适配器未检测到
2. 蓝牙适配器被其他集成占用
3. Home Assistant没有蓝牙权限
4. 蓝牙适配器驱动问题

**解决方案**：

**步骤1：检查蓝牙适配器状态**
```
通过UI检查：
设置 → 系统 → 硬件
查看"蓝牙"部分

应该看到：
- 蓝牙适配器型号
- 适配器状态（在线/离线）
- 适配器地址（MAC地址）
```

**步骤2：检查蓝牙适配器数量**

集成要求至少1个支持连接的蓝牙适配器。

**检查方法**：
```yaml
# 使用开发者工具
设置 → 开发者工具 → 服务

域: bluetooth_adapters
服务: get_scanners
服务数据: {}

执行后查看：
- scanner_count: 扫描器数量
- connectable_count: 可连接扫描器数量
```

**要求**：
- `connectable_count >= 1` - 至少1个可连接适配器
- 如果 `connectable_count = 0`，需要：
  - 添加蓝牙适配器
  - 或添加ESP-Proxy

**步骤3：检查ESP-Proxy（如果使用）**

```
ESP Home → 设备 → 选择ESP-Proxy
查看状态：
- Wi-Fi：已连接
- API：已连接
- 蓝牙代理：已启用

如果状态异常：
1. 重启ESP-Proxy
2. 检查ESP-Proxy与HA的网络连接
3. 更新ESP-Proxy固件
```

**步骤4：检查Home Assistant权限**

**Home Assistant OS**：
```
设置 → 系统 → 硬件
查看蓝牙权限是否启用
```

**Home Assistant Container（Docker）**：
```bash
# 检查容器是否可以访问蓝牙
docker exec home-assistant ls -la /dev/bus/usb/

# 应该看到蓝牙设备
# 如果没有，需要添加设备映射
docker run --device=/dev/bus/usb/...
```

**Home Assistant Core**：
```bash
# 检查用户是否在蓝牙组
groups

# 如果不在，添加到蓝牙组
sudo usermod -a -G bluetooth homeassistant
```

**步骤5：手动测试蓝牙适配器**

**Linux命令**：
```bash
# 检查蓝牙适配器
hciconfig -a

# 应该看到：
# hci0:	Type: Primary  Bus: USB
# 	BD Address: XX:XX:XX:XX:XX:XX
# 	UP RUNNING

# 如果显示DOWN：
sudo hciconfig hci0 up
```

**步骤6：查看详细日志**

```
设置 → 系统 → 日志
选择"调试"级别
搜索: "bluetooth" 或 "adapter"

正常日志：
INFO:蓝牙适配器已检测到: hci0
INFO:扫描器已就绪

错误日志：
ERROR:没有可用的蓝牙适配器
WARNING:蓝牙适配器不支持BLE
```

**诊断信息收集**：

提交问题时提供：
```
1. 蓝牙适配器型号
2. Home Assistant版本
3. 安装类型（OS/Container/Core）
4. 蓝牙适配器状态（设置 → 系统 → 硬件）
5. 日志（搜索"bluetooth"）
```

**临时解决方案**：

如果没有蓝牙适配器，可以使用ESP-Proxy：
```
1. 准备ESP32设备
2. 安装ESPHome
3. 配置蓝牙代理
4. 将ESP-Proxy添加到Home Assistant
5. 通过ESP-Proxy连接设备
```

ESP-Proxy参考：
- [ESPHome蓝牙代理文档](https://esphome.io/components/bluetooth_proxy.html)
- 推荐硬件：ESP32-POE-ISO-EA

## 二、扫描和连接问题

### 问题3：扫描不到设备

**症状**：
- 配置时扫描列表为空
- 无法发现设备

**可能原因**：
1. 设备未开机
2. 设备距离太远
3. 蓝牙适配器未工作
4. 设备被其他设备连接

**解决方案**：

**步骤1：确认设备状态**
- ✅ 设备已开机（检查指示灯）
- ✅ 设备电量充足
- ✅ 设备未连接到其他设备（如手机）

**步骤2：靠近设备**
- 将设备靠近 Home Assistant（< 1米）
- 确保没有障碍物阻隔

**步骤3：检查蓝牙适配器**
```bash
# Linux
hciconfig -a

# 应该看到类似输出：
# hci0:	Type: Primary  Bus: USB
# 	BD Address: XX:XX:XX:XX:XX:XX  ACL MTU: 1021:8  SCO MTU: 64:1
# 	UP RUNNING 
# 	RX bytes:1234 acl:0 sco:0 events:123 errors:0
# 	TX bytes:5678 acl:0 sco:0 commands:123 errors:0
```

**步骤4：手动测试扫描**
```bash
# 使用 bluetoothctl
bluetoothctl
scan on
# 查看是否能扫描到设备
scan off
exit
```

**步骤5：查看日志**
```
设置 → 系统 → 日志
搜索 "bluetooth" 或 "scanner"
```

---

### 问题4：连接频繁断开

**症状**：
- 设备连接后很快断开
- 连接状态频繁切换

**可能原因**：
1. 蓝牙信号不稳定
2. 设备距离太远
3. 设备电量不足
4. 其他蓝牙设备干扰
5. 设备固件问题

**解决方案**：

**步骤1：检查信号强度**
```
设置 → 设备与服务 → BLE 防丢标签
查看 RSSI 传感器
```
- **RSSI < -80 dBm**：信号太差，需要靠近
- **RSSI > -60 dBm**：信号良好

**步骤2：靠近设备**
- 将设备靠近（< 5米）
- 移除障碍物
- 避免金属遮挡

**步骤3：检查设备电量**
- 如果电量 < 20%，请充电
- 低电量可能导致连接不稳定

**步骤4：检查干扰源**
- 微波炉
- 无线路由器（2.4GHz）
- 其他蓝牙设备
- 尽量远离这些设备

**步骤5：使用 ESPHome 代理**
- 如果距离较远，考虑使用 ESPHome 蓝牙代理
- 参考：[ESPHome 蓝牙代理](https://esphome.io/components/bluetooth_proxy.html)

**步骤6：调整配置**
```yaml
# 增加连接超时
connection_timeout_sec: 30

# 增加重连延迟
reconnect_delay_sec: 10
```

---

### 问题5：连接后立即断开

**症状**：
- 设备显示"已连接"
- 几秒后立即断开
- 循环重复

**可能原因**：
1. 设备被其他应用抢占
2. 蓝牙适配器驱动问题
3. 设备固件不兼容
4. 服务发现失败

**解决方案**：

**步骤1：检查设备是否被其他应用连接**
- 关闭手机上的蓝牙应用
- 确保设备只连接到 Home Assistant

**步骤2：查看详细日志**
```
设置 → 系统 → 日志
选择 "正确" 日志级别
搜索 "anti_loss_tag"
```

**步骤3：重启蓝牙适配器**
```bash
# Home Assistant OS
hassio hardware audio restart

# Linux
sudo systemctl restart bluetooth
```

**步骤4：更新设备固件**
- 联系设备供应商获取最新固件
- 按照设备说明更新固件

## 三、数据和事件问题

### 问题6：电量不更新

**症状**：
- 电量传感器一直显示相同值
- 电量显示"未知"

**可能原因**：
1. 轮询间隔太长
2. 设备不支持 2a19 特征
3. 设备未连接
4. 读取失败

**解决方案**：

**步骤1：检查设备连接状态**
```
设置 → 设备与服务 → BLE 防丢标签
查看"连接状态"二进制传感器
```
- 如果是"关"（未连接），电量不会更新

**步骤2：检查轮询间隔**
```
设置 → 设备与服务 → BLE 防丢标签 → 配置
查看"电量轮询间隔"
```
- 如果设置过长（如 1440 分钟），会很久才更新
- 建议设置为 360 分钟（6小时）

**步骤3：手动触发电量读取**
```
设置 → 设备与服务 → BLE 防丢标签
点击"重新加载"按钮
```

**步骤4：检查设备是否支持电量读取**
```bash
# 查看日志
设置 → 系统 → 日志
搜索 "2a19" 或 "battery"
```

如果看到"设备不支持电量读取"：
- 这是设备硬件限制
- 无法通过软件修复
- 电量传感器会显示"未知"

**步骤5：检查错误日志**
```
设置 → 系统 → 日志
搜索 "read_battery" 或 "gatt"
```

### 问题7：按钮事件不触发

**症状**：
- 按下设备按钮，Home Assistant 没有反应
- 自动化不执行

**可能原因**：
1. 通知未开启
2. 设备不支持 ffe1 特征
3. 事件订阅失败
4. 自动化配置错误

**解决方案**：

**步骤1：检查设备是否支持按钮事件**
- 确认设备规格支持按钮功能
- 查看 [协议规范](../05-协议规范/协议规范.md)

**步骤2：检查通知是否开启**
```bash
# 查看日志
设置 → 系统 → 日志
搜索 "ffe1" 或 "notify"
```

应该看到类似：
```
INFO:FFE1 通知已开启
```

如果看到"开启通知失败"：
- 设备可能不支持 ffe1 特征
- 这是设备硬件限制

**步骤3：测试事件是否触发**
```bash
# 查看日志
设置 → 系统 → 日志
搜索 "button" 或 "event"
```

按下设备按钮时，应该看到：
```
INFO:收到按钮事件: 单击
DEBUG:Firing event: anti_loss_tag_button_event
```

**步骤4：检查自动化配置**
```yaml
# 示例自动化
automation:
  - alias: "测试按钮事件"
    trigger:
      - platform: event
        event_type: anti_loss_tag_button_event
    action:
      - service: logger.log
        data:
          message: "按钮事件触发！"
```

**步骤5：使用事件监听器**
```
设置 → 开发者工具 → 事件
监听：anti_loss_tag_button_event
```

按下设备按钮，查看是否显示事件。

### 问题8：报警不响

**症状**：
- 触发报警后，设备没有反应
- 断开连接时不报警

**可能原因**：
1. 设备不支持 2a06 特征
2. 2a06 写入方式错误
3. 设备电量不足
4. 设备静音模式

**解决方案**：

**步骤1：手动测试报警**
```
设置 → 设备与服务 → BLE 防丢标签
点击"触发报警"按钮
```

**步骤2：检查设备是否支持报警**
```bash
# 查看日志
设置 → 系统 → 日志
搜索 "2a06" 或 "alarm"
```

如果看到"设备不支持即时报警"：
- 这是设备硬件限制
- 无法通过软件修复

**步骤3：检查设备电量**
- 设备电量过低可能无法触发报警
- 建议电量 > 20%

**步骤4：检查设备静音模式**
- 某些设备有静音开关
- 检查设备是否设置为静音

**步骤5：查看详细日志**
```bash
# 启用调试日志
# configuration.yaml
logger:
  default: info
  logs:
    custom_components.anti_loss_tag: debug
    bleak: debug
```

重启后查看日志。

## 四、性能和稳定性问题

### 问题9：Home Assistant 运行缓慢

**症状**：
- 添加多个设备后 HA 变慢
- CPU 使用率升高
- 日志中有大量错误

**可能原因**：
1. 连接数超过限制
2. 轮询频率太高
3. 蓝牙适配器性能不足
4. 并发连接冲突

**解决方案**：

**步骤1：检查设备数量**
- ESPHome 代理建议不超过 3-4 个设备
- USB 适配器建议不超过 5-8 个设备

**步骤2：调整轮询间隔**
```yaml
# 降低轮询频率
battery_poll_interval_min: 720  # 增加到12小时
rssi_poll_interval_min: 30      # 增加到30分钟
```

**步骤3：关闭维持连接**
```yaml
maintain_connection: false  # 关闭常驻连接
```

**步骤4：使用多个蓝牙适配器**
- 添加更多 USB 蓝牙适配器
- 或使用多个 ESPHome 代理
- 分散设备负载

**步骤5：检查资源使用**
```bash
# SSH 到 Home Assistant
top -bn1 | head -20
```

查看 CPU 和内存使用情况。

---

### 问题10：大量错误日志

**症状**：
- 日志中有大量重复错误
- 日志文件快速增长

**常见错误类型**：

**错误1：连接超时**
```
ERROR:连接超时: AA:BB:CC:DD:EE:FF
```

**解决方案**：
- 增加连接超时时间
- 检查蓝牙信号
- 靠近设备

**错误2：GATT 操作失败**
```
ERROR:写入失败: ...
ERROR:读取失败: ...
```

**解决方案**：
- 检查设备是否连接
- 查看设备是否支持该特征
- 增加重试延迟

**错误3：设备离线**
```
WARNING:设备离线: AA:BB:CC:DD:EE:FF
```

**解决方案**：
- 这是正常的，等待自动重连
- 如果长时间离线，检查设备状态

## 八、2025年已知问题和解决方案

### 问题1：ESPHome 2025.6.0连接问题（已修复）

**影响版本**：
- ESPHome: 2025.6.0
- Home Assistant: 2025.6.x

**症状**：
- BLE设备连接后立即断开
- 传感器显示不可用
- 日志显示连接错误

**原因**：
ESPHome 2025.6.0的蓝牙代理有BUG，导致主动连接不稳定。

**解决方案**：

**方案1：升级ESPHome（推荐）**
```
ESP Home → 设备 → ESP-Proxy → 更新
升级到 ESPHome 2025.6.1 或更高版本
```

**方案2：降级ESPHome**

### 问题2：蓝牙适配器权限问题（Container）

**影响版本**：
- Home Assistant Container
- Linux系统

**症状**：
- 添加集成时提示"蓝牙适配器未就绪"
- 日志显示"Permission denied"访问蓝牙设备

**原因**：
Home Assistant容器用户没有访问蓝牙设备的权限。

**解决方案**：

**检查权限**：
```bash
# 进入容器
docker exec -it home-assistant bash

# 检查蓝牙设备
ls -la /dev/bus/usb/

# 检查用户组
id
```

**添加权限**：

**方法1：添加设备映射**
```yaml
# docker-compose.yml
services:
  home-assistant:
    devices:
      - /dev/bus/usb:/dev/bus/usb
      - /dev/ttyACM0:/dev/ttyACM0
```

**方法2：添加用户到组**
```bash
# 查看蓝牙设备组
ls -la /dev/bus/usb/001/

# 添加用户到组（假设组名为usb）
sudo usermod -a -G usb $(id -u)
```

**方法3：使用--privileged（不推荐）**
```bash
docker run --privileged home-assistant
```

**重启容器**：
```bash
docker restart home-assistant
```

**验证**：
```
设置 → 系统 → 硬件
查看蓝牙适配器是否显示
```

### 问题4：USB蓝牙适配器不工作

**影响版本**：
- 所有版本
- 特定硬件

**症状**：
- 蓝牙适配器未检测到
- 扫描不到设备

**诊断步骤**：

**1. 检查硬件兼容性**
```
推荐适配器（HA开发团队测试）：
- Feasycom FSC-BP119 (CSR8510A10)
- Cambridge Silicon Radio (CSR) 基于芯片
- Olimex ESP32-POE-ISO-EA (ESP-Proxy)

不推荐适配器：
- Broadcom芯片（Linux支持差）
- Intel无线网卡（蓝牙部分）
```

**2. 检查驱动加载**
```bash
# Linux
lsmod | grep bluetooth

# 应该看到：
# bluetooth
- btrtl
- btmrvl
- btusb

如果没有：
sudo modprobe bluetooth
sudo modprobe btusb
```

**3. 检查设备识别**
```bash
# 查看USB设备
lsusb

# 查找蓝牙适配器
# 应该看到类似：
# Bus 001 Device 005: ID 0a12:0001 Cambridge Silicon Radio

# 查看详细信息
usb-devices | grep -A 10 "Bluetooth"
```

**4. 强制重启蓝牙**
```bash
# Linux
sudo systemctl stop bluetooth
sudo systemctl start bluetooth

# 或
sudo rfkill unblock bluetooth
```

**5. Home Assistant OS特殊处理**
```
Home Assistant OS → 设置 → 系统 → 硬件
查看蓝牙适配器状态

如果未显示：
1. 关闭Home Assistant
2. 关闭电源
3. 重新插入USB适配器
4. 开机并启动Home Assistant
5. 检查是否识别
```

**适配器位置建议**：
- ✅ 使用USB延长线（避免USB 3.0干扰）
- ✅ 远离无线路由器（2.4GHz干扰）
- ✅ 避免金属遮挡
- ❌ 不要直接插在路由器USB口

### 问题5：多个设备连接失败

**影响版本**：
- 所有版本
- 连接设备超过3-5个

**症状**：
- 添加第4个设备时连接失败
- 日志显示"连接槽位不足"

**原因**：
ESP-Proxy和USB适配器有连接数限制。

**解决方案**：

**检查当前连接数**：
```yaml
# 使用开发者工具
设置 → 开发者工具 → 模板

模板：
{{ states('sensor.bluetooth_adapters_adapter_connected_devices') }}

或查看网络拓扑：
设置 → 设备与服务 → 蓝牙 → 配置
查看网络拓扑 → 连接数统计
```

**连接数限制**：
```
ESP-Proxy: 2-3个并发连接
USB适配器: 5-8个设备（取决于硬件）
内置适配器: 通常3-5个设备
```

**优化方案**：

**方案1：关闭"维持连接"**
```
设置 → 设备与服务 → BLE 防丢标签 → 设备 → 配置
维持连接：关闭 ⛔

优点：减少并发连接
缺点：按钮事件延迟增加
```

**方案2：增加适配器**
```
添加更多蓝牙适配器：
- USB适配器（最多3-5个）
- ESP-Proxy（最多2-3个设备）

配置：
设置 → 设备与服务 → 蓝牙 → 配置
添加适配器
```

**方案3：使用多个ESP-Proxy**
```
1. 部署多个ESP-Proxy
2. 分散设备连接
3. 避免单个代理过载

布局示例：
- ESP-Proxy-1（客厅）：2-3个设备
- ESP-Proxy-2（卧室）：2-3个设备
- 内置适配器：1-2个设备
```

**方案4：调整轮询间隔**
```
降低轮询频率减少连接时间：

电量轮询：360分钟 → 720分钟
RSSI轮询：10分钟 → 30分钟
```

**验证优化效果**：
```
1. 查看网络拓扑
   连接数应 ≤ 限制

2. 查看日志
   应该减少"连接槽位不足"错误

3. 测试所有设备
   确认所有设备能正常连接
```

### 问题6：蓝牙信号弱或不稳定

**影响版本**：
- 所有版本
- 特定环境

**症状**：
- 设备频繁断开
- RSSI值低于-80dBm
- 连接状态不稳定

**诊断**：

**查看信号强度**：
```
设置 → 设备与服务 → BLE 防丢标签
查看 RSSI 传感器

信号判断：
- -50 到 -40 dBm：非常好（< 1米）
- -60 到 -50 dBm：良好（1-5米）
- -70 到 -60 dBm：一般（5-10米）
- -80 到 -70 dBm：差（10-20米）
< -80 dBm：不可用
```

**解决方案**：

**方案1：优化适配器位置**
```
1. 将适配器放置在中心位置
2. 避开金属物体
3. 远离干扰源（路由器、微波炉）
4. 使用USB延长线调整位置
```

**方案2：使用ESP-Proxy扩展**
```
1. 在信号弱区域添加ESP-Proxy
2. ESP-Proxy通过Wi-Fi连接到HA
3. 设备连接到附近的ESP-Proxy

优点：
- 扩大覆盖范围
- 减少单个适配器负载
- 提高连接稳定性
```

**方案3：调整广播功率**
```
ESP Home → ESP-Proxy配置
TX Power: +6dBm（提高功率）

注意：
- 功率越高，功耗越大
- 可能增加干扰
```

**方案4：优化Wi-Fi信道**
```
2.4GHz Wi-Fi和蓝牙使用相同频段

Wi-Fi信道建议：
- 使用信道1、6、11（避免重叠）
- 远离蓝牙设备
- 使用5GHz Wi-Fi（如果可能）
```

**环境优化检查清单**：
- [ ] 适配器位置居中
- [ ] 避开金属物体
- [ ] 远离干扰源
- [ ] 使用ESP-Proxy扩展
- [ ] 优化Wi-Fi信道
- [ ] 调整设备轮询间隔

### 问题7：bleak 2.0.0版本兼容性问题

**影响版本**：
- bleak: 2.0.0
- Home Assistant: 2026.1.x
- 后端: BlueZ（Linux）

**症状**：
- 设备连接成功
- 启用通知失败（start_notify）
- 日志显示"Feature unavailable"或"Not supported"

**原因**：

**解决方案**：

**检查bleak版本**：
```bash
# 进入Home Assistant环境
hass-cli homeassistant --version

# 检查bleak版本
pip show bleak
```

**方案1：升级bleak（推荐）**
```bash
# 升级到bleak 2.1.0或更高版本
pip install --upgrade "bleak>=2.1.0"

# 重启Home Assistant
hass-cli homeassistant restart
```

**方案2：降级bleak**
```bash
# 如果无法升级，降级到1.0.1版本
pip install "bleak==1.0.1"

# 重启Home Assistant
hass-cli homeassistant restart
```

**方案3：等待Home Assistant更新**
```
Home Assistant 2026.1.x会包含bleak 2.1.0+
更新到最新版本
```

**验证修复**：
```
1. 重新加载蓝牙集成
2. 连接设备
3. 查看传感器是否更新
4. 检查日志无start_notify错误
```

**相关链接**：
- [bleak Release 2.1.0](https://github.com/hbldh/bleak/releases/tag/v2.1.0)
- [bleak Issue #1180](https://github.com/hbldh/bleak/issues/1180)

**注意事项**：
- ✅ 推荐使用bleak 2.1.0+（修复了已知问题）
- ⚠️ bleak 2.0.0存在多个兼容性问题
- ⚠️ 其他集成可能依赖特定bleak版本（如renogy-ble）

### 问题8：eq3btsmart频繁断开（2025.7+）

**影响版本**：
- Home Assistant: 2025.7.0及以后
- 集成: eq3btsmart（恒温器）

**症状**：
- 设备连接后1-2分钟内断开
- 日志显示"Device disconnected"或"Connection lost"
- 传感器数据更新不稳定

**原因**：
2025.7版本后，蓝牙连接管理策略发生变化，导致某些设备（特别是eq3btsmart恒温器）的连接稳定性下降。

**解决方案**：

**方案1：升级Home Assistant（推荐）**
```
检查更新：
设置 → 系统 → 更新

如果可用：
1. 备份Home Assistant
2. 更新到最新版本
3. 重启系统
4. 重新添加设备
```

**方案2：调整连接参数**
```yaml
# configuration.yaml（如果支持）

# 增加连接超时
bluetooth:
  connection_timeout: 60  # 增加到60秒

# 或通过集成配置调整
```

**方案3：关闭"维持连接"**
```
设置 → 设备与服务 → eq3btsmart → 设备 → 配置
维持连接：关闭 ⛔

优点：减少断开重连频率
缺点：按钮事件延迟增加
```

**方案4：使用ESP-Proxy**
```
1. 部署ESP-Proxy靠近设备
2. 设备通过ESP-Proxy连接
3. 减少直接连接的不稳定性

配置：
ESP Home → ESP-Proxy → 蓝牙
启用"维持连接"
```

**方案5：调整广告间隔**
```
如果设备支持：
ESP Home → 设备配置
Advertising Interval: 1000ms（降低频率）
```

**监控连接质量**：
```yaml
# 使用自动化监控断开次数

automation:
  - alias: "监控BLE连接"
    trigger:
      - platform: state
        entity_id: sensor.eq3btsmart_connection_status
        to: "disconnected"
    action:
      - service: log.log
        data:
          message: "eq3btsmart断开连接: {{ now() }}"
      - service: notify.notify
        data:
          message: "⚠️ 恒温器连接断开，请检查设备"
```

**验证修复**：
```
1. 连接设备
2. 观察30分钟
3. 查看日志中"disconnected"次数
4. 确认传感器数据稳定更新
```

**相关链接**：
- [Home Assistant Community讨论](https://community.home-assistant.io/t/eq3btsmart-frequent-disconnections-after-2025-7/903245)
- [蓝牙连接管理文档](https://www.home-assistant.io/integrations/bluetooth/)

**注意事项**：
- ✅ 使用最新稳定版Home Assistant
- ⚠️ 2025.7.0-2025.7.2受影响最严重
- ⚠️ 关闭"维持连接"会影响响应速度
- ✅ ESP-Proxy可以提高稳定性
