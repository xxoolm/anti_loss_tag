## 一、蓝牙适配器状态监控

### 1.1 适配器状态实体

**实体列表**：

| Entity ID | 说明 | 更新频率 |
|-----------|------|----------|
| `sensor.bluetooth_adapter_connected_devices` | 已连接设备数 | 实时 |
| `sensor.bluetooth_adapter_active_connections` | 活跃连接数 | 实时 |
| `sensor.bluetooth_adapter_scanning` | 是否正在扫描 | 实时 |
| `sensor.bluetooth_adapter_last_seen` | 最后发现时间 | 实时 |

**查看方法**：
```
设置 → 开发者工具 → 状态
搜索: "bluetooth_adapter"
```

### 1.2 适配器健康指标

**指标说明**：

#### 1. 连接健康度
```
计算公式：(活跃连接数 / 最大连接数) * 100%

健康判断：
- < 50%: 健康 ✅
- 50-80%: 良好 ⚠️
- > 80%: 拥挤 ❌
```

#### 2. 扫描效率
```
计算：(发现的设备数 / 扫描时间)

正常值：
- > 1 设备/秒: 高效 ✅
- 0.5-1 设备/秒: 正常 ⚠️
- < 0.5 设备/秒: 低效 ❌
```

#### 3. 连接成功率
```
计算：(成功连接数 / 尝试连接数) * 100%

要求：
- > 90%: 良好 ✅
- 70-90%: 一般 ⚠️
- < 70%: 需要优化 ❌
```

### 1.3 适配器诊断命令

**检查适配器状态**：
```yaml
# 使用开发者工具 → 服务
域: bluetooth_adapters
服务: adapter_diagnostics
服务数据: {}
```

**获取详细适配器信息**：
```bash
# SSH到Home Assistant
bluetoothctl --list
# 列出所有适配器

bluetoothctl info hci0
# 显示适配器详细信息
```

## 二、连接质量分析

### 2.1 连接质量指标

**指标列表**：

| 指标 | 说明 | 良好值 | 问题值 |
|------|------|--------|--------|
| **RSSI** | 信号强度 | > -60dBm | < -80dBm |
| **连接稳定性** | 断开频率 | < 1次/小时 | > 5次/小时 |
| **延迟** | 响应时间 | < 200ms | > 500ms |
| **重连次数** | 重连频率 | < 3次/天 | > 10次/天 |

### 2.2 查看连接质量

**通过实体**：
```
sensor.{设备名}_rssi                    # 信号强度
sensor.{设备名}_connection_quality     # 连接质量
sensor.{设备名}_last_reconnect          # 最后重连时间
```

**通过日志**：
```
设置 → 系统 → 日志
搜索: "connection" OR "quality"
```

### 2.3 连接质量优化

#### 场景1：信号弱
```
问题：RSSI < -80dBm

解决：
1. 靠近设备
2. 使用ESP-Proxy
3. 优化适配器位置
4. 调整广播功率
```

#### 场景2：频繁断开
```
问题：重连次数 > 10次/天

诊断：
1. 查看连接稳定性日志
2. 检查干扰源
3. 检查适配器负载

解决：
1. 关闭"维持连接"
2. 增加适配器
3. 优化轮询间隔
```

#### 场景3：延迟高
```
问题：响应时间 > 500ms

诊断：
1. 查看连接状态
2. 检查网络拓扑
3. 查看适配器负载

解决：
1. 使用直接连接（不用代理）
2. 减少设备数量
3. 优化轮询频率
```

## 三、性能监控

### 3.1 Home Assistant性能

**监控指标**：

| 指标 | 正常值 | 问题值 |
|------|--------|--------|
| **CPU使用率** | < 30% | > 70% |
| **内存使用** | < 70% | > 90% |
| **蓝牙任务数** | < 10 | > 20 |

**查看方法**：
```
设置 → 系统 → 服务器管理
查看CPU、内存、进程
```

### 3.2 蓝牙集成性能

**优化检查清单**：

- [ ] 设备数量 < 适配器限制
- [ ] 轮询间隔合理（电量 ≥ 360分钟）
- [ ] 维持连接关闭（省电）
- [ ] ESP-Proxy分布合理
- [ ] 无频繁重连

**性能优化建议**：

#### 1. 减少轮询频率
```yaml
# 优化前
battery_poll_interval: 30   # 太频繁
rssi_poll_interval: 5       # 太频繁

# 优化后
battery_poll_interval: 360  # 6小时
rssi_poll_interval: 10      # 10分钟
```

#### 2. 关闭不必要的维持连接
```yaml
# 只对需要实时响应的设备开启
设备1: maintain_connection = true
设备2: maintain_connection = false  # 推荐
```

#### 3. 分散设备到多个适配器
```
适配器1: 2-3个设备
适配器2: 2-3个设备
ESP-Proxy-1: 2个设备
ESP-Proxy-2: 2个设备
```

## 四、调试技巧

### 4.1 启用详细日志

**临时启用**（重启后失效）：
```
设置 → 系统 → 日志
日志级别：调试
```

**永久启用**：
```yaml
# configuration.yaml
logger:
  default: info
  logs:
    custom_components.anti_loss_tag: debug
    bleak: debug
    bleak.exc: debug
    bluetooth_adapters: debug
    homeassistant.components.bluetooth: debug
```

**重启后生效**：
```
设置 → 系统 → 服务器管理 → 重启
```

### 4.2 查看蓝牙事件

**方法1：通过开发者工具**
```
设置 → 开发者工具 → 事件
监听事件类型:
- bluetooth_device_connected
- bluetooth_device_disconnected
- bluetooth_device_found
```

**方法2：通过日志**
```
设置 → 系统 → 日志
搜索: "bluetooth" OR "adapter"
```

### 4.3 捕获数据包

**使用bluetoothctl**：
```bash
# SSH到Home Assistant
sudo bluetoothctl -a

# 启用监控
# 选择适配器
# 启动扫描
```

**查看BLE通信**：
```bash
# 使用Wireshark（需要外置捕获器）
sudo hcitool lescan
# 或使用bleah
bleah -b <MAC地址>
```

### 4.4 常见诊断命令

**检查蓝牙服务状态**：
```bash
sudo systemctl status bluetooth
```

**重启蓝牙服务**：
```bash
sudo systemctl restart bluetooth
```

**查看连接的设备**：
```bash
bluetoothctl paired-devices
bluetoothctl connect <MAC>
bluetoothctl disconnect <MAC>
```

## 五、性能基准测试

### 5.1 连接性能基准

**测试场景**：

| 场景 | 预期时间 | 测试方法 |
|------|----------|----------|
| 冷启动连接 | < 10秒 | 重启HA后首次连接 |
| 热连接 | < 3秒 | 断开后立即重连 |
| 数据读取 | < 2秒 | 读取电量/RSSI |
| 报警响应 | < 1秒 | 触发报警到接收 |

### 5.2 压力测试

**测试适配器极限**：
```
1. 逐步增加设备数量（2 → 4 → 6 → 8）
2. 观察连接成功率
3. 观察重连频率
4. 找到适配器承载上限
```

**测试轮询影响**：
```
1. 设置最小轮询间隔（5分钟）
2. 观察CPU/内存使用
3. 逐步增加间隔
4. 找到最佳平衡点
```

## 六、高级故障排除

### 6.1 蓝牙适配器问题

**问题：适配器不可用**
```
诊断：
1. 检查适配器状态
   bluetoothctl --list

2. 检查USB权限
   ls -la /dev/bus/usb/

3. 检查驱动
   dmesg | grep bluetooth

解决：
1. 添加USB设备到Docker
2. 检查蓝牙服务状态
3. 更新蓝牙驱动
```

**问题：适配器性能差**
```
诊断：
1. 查看适配器负载
2. 检查连接数量
3. 查看信号强度

解决：
1. 减少连接设备
2. 增加ESP-Proxy
3. 升级适配器硬件
```

### 6.2 设备连接问题

**问题：设备无法发现**
```
诊断：
1. 检查广播间隔
2. 检查RSSI阈值
3. 检查MAC地址过滤

解决：
1. 延长扫描超时
2. 降低RSSI阈值
3. 添加MAC地址到白名单
```

**问题：连接频繁断开**
```
诊断：
1. 查看连接稳定性日志
2. 检查信号强度
3. 检查适配器负载

解决：
1. 优化适配器位置
2. 减少轮询频率
3. 关闭维持连接
```

### 6.3 数据异常

**问题：电量显示异常**
```
诊断：
1. 查看原始数据日志
2. 检查GATT读取结果
3. 验证数据解析逻辑

解决：
1. 重启设备
2. 重置传感器
3. 更新固件
```

**问题：报警不触发**
```
诊断：
1. 检查距离阈值设置
2. 查看RSSI历史
3. 检查报警状态

解决：
1. 降低距离阈值
2. 调整轮询间隔
3. 启用详细日志
```
