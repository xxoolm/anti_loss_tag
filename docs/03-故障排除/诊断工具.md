## 二、Home Assistant内置诊断工具

### 2.1 开发者工具 - 状态

**用途**：查看所有实体的当前状态

**步骤**：
1. 进入 **设置** → **开发者工具**
2. 点击 **状态** 标签
3. 在搜索框中输入您的设备名称

**查看内容**：
- Entity ID
- Friendly Name
- 状态值
- 最后更新时间
- 属性

**示例**：
```
Entity ID: sensor.my_keys_battery
State: 85
Attributes:
  unit_of_measurement: %
  device_class: battery
  friendly_name: 我的钥匙 电量
```

---

### 2.2 开发者工具 - 事件

**用途**：监听和查看实时事件

**步骤**：
1. 进入 **设置** → **开发者工具**
2. 点击 **事件** 标签
3. 在 **监听事件** 中输入事件名称
4. 点击 **开始监听**

**常用事件**：
- `anti_loss_tag_button_event` - 按钮事件
- `state_changed` - 状态变化

**示例事件数据**：
```json
{
  "entity_id": "event.my_keys_button_event",
  "event_type": "单击",
  "raw_data": "01000000000000"
}
```

---

### 2.3 开发者工具 - 模板

**用途**：测试Jinja2模板和表达式

**步骤**：
1. 进入 **设置** → **开发者工具**
2. 点击 **模板** 标签
3. 输入模板表达式
4. 点击 **渲染模板**

**常用模板**：

**查找所有相关实体**：
```jinja2
{% for entity in states.sensor if 'my_keys' in entity.entity_id %}
{{ entity.entity_id }}: {{ entity.state }}
{% endfor %}
```

**获取设备属性**：
```jinja2
{{ state_attr('sensor.my_keys_battery', 'device_class') }}
```

**格式化RSSI值**：
```jinja2
{{ states('sensor.my_keys_rssi') }} dBm
```

### 3.1 查看日志

**步骤**：
1. 进入 **设置** → **系统**
2. 点击 **日志** 标签
3. 选择日志级别：
   - **全部** - 所有日志
   - **调试** - 详细调试信息
   - **信息** - 一般信息
   - **警告** - 警告和错误
   - **错误** - 仅错误

---

### 3.2 搜索关键字

**常用搜索关键字**：

```
anti_loss_tag
bleak
bluetooth
gatt
connection
battery
error
warning
```

**搜索方法**：
1. 在日志页面的搜索框中输入关键字
2. 使用正则表达式：`bleak.*error`
3. 使用多个关键字：`anti_loss_tag.*error`

### 3.3 启用调试日志

**临时启用**（重启后失效）：
1. 进入 **设置** → **系统** → **日志**
2. 选择 **调试** 日志级别
3. 重启集成

# configuration.yaml

  default: info
  logs:
    custom_components.anti_loss_tag: debug
    bleak: debug
    bleak.exc: debug

**重启后生效**：
```
设置 → 系统 → 服务器管理 → 重启
```

### 4.4 检查蓝牙适配器可用性（2025标准）

**使用官方API检查**：

**方法1：通过开发者工具**
```
设置 → 开发者工具 → 服务

域: bluetooth_adapters
服务: async_scanner_count
服务数据: {}

执行结果示例：
- connectable: 1 （有1个可连接适配器）
- all: 2 （总共有2个适配器）
```

**方法2：通过Python脚本**
```python
# 在Home Assistant配置目录中运行
python3 << 'EOF'
from homeassistant.components import bluetooth
import homeassistant.const as const

# 获取扫描器数量
count = bluetooth.async_scanner_count(hass, connectable=True)
print(f"可连接扫描器数量: {count}")

if count == 0:
    print("❌ 没有可用的蓝牙适配器")
    print("请添加蓝牙适配器或ESP-Proxy")
else:
    print(f"✅ 有 {count} 个可用的蓝牙适配器")
EOF
```

**适配器状态判断**：
```
connectable_count >= 1: ✅ 正常
connectable_count == 0: ❌ 没有可用的蓝牙适配器
  - 需要添加USB蓝牙适配器
  - 或添加ESP-Proxy
```

**检查ESP-Proxy状态**：
```
1. 进入ESP Home
2. 选择ESP-Proxy设备
3. 查看状态：
   - 蓝牙代理：已启用
   - API：已连接
   - Wi-Fi：已连接
```

**适配器诊断流程**：
```
1. 检查适配器数量
   bluetooth.async_scanner_count()
   
2. 如果为0，检查原因：
   - 适配器硬件未连接
   - 适配器驱动未加载
   - 适配器被其他集成占用
   
3. 查看详细错误
   日志搜索: "bluetooth" + "adapter"
   
4. 根据错误类型解决
   - 硬件问题：重新连接适配器
   - 驱动问题：重启系统
   - 权限问题：添加蓝牙权限
```

## 五、常见问题诊断流程

### 问题1：扫描不到设备

**诊断流程**：

1. **检查设备状态**
   ```
   设备是否开机？
   设备电量是否充足？
   设备是否在范围内（< 5米）？
   ```

2. **检查蓝牙适配器**
   ```
   设置 → 系统 → 硬件
   查看蓝牙是否检测到
   ```

3. **查看日志**
   ```
   设置 → 系统 → 日志
   搜索: "scanner" 或 "bluetooth"
   ```

4. **手动扫描测试**
   ```bash
   bluetoothctl
   scan on
   # 查看设备是否出现在列表中
   ```

---

### 问题2：连接失败

**诊断流程**：

1. **检查设备是否被占用**
   ```
   关闭手机蓝牙
   卸载手机上的防丢标签App
   重试连接
   ```

2. **检查信号强度**
   ```
   将设备靠近（< 0.5米）
   避开金属障碍物
   ```

3. **查看详细日志**
   ```
   启用调试日志
   设置 → 系统 → 日志
   搜索: "connection" 或 "gatt"
   ```

4. **分析错误原因**
   ```
   常见错误：
   - "Device not found" - 设备未发现
   - "Connection timeout" - 连接超时
   - "GATT error" - GATT操作失败
   ```

---

### 问题3：按钮事件不触发

**诊断流程**：

1. **确认设备已连接**
   ```
   查看连接状态传感器
   应该显示 "on"
   ```

2. **确认通知已开启**
   ```
   查看日志
   搜索: "notify" 或 "FFE1"
   应该看到 "FFE1 通知已开启"
   ```

3. **使用事件监听器**
   ```
   设置 → 开发者工具 → 事件
   监听: anti_loss_tag_button_event
   按下设备按钮
   查看是否有事件
   ```

4. **创建调试自动化**
   ```yaml
   automation:
     - alias: "调试按钮事件"
       trigger:
         - platform: event
           event_type: anti_loss_tag_button_event
       action:
         - service: logger.log
           data:
             message: "按钮事件: {{ trigger.event.data }}"
   ```

---

### 问题4：电量不更新

**诊断流程**：

1. **确认轮询间隔**
   ```
   设置 → 设备与服务 → BLE 防丢标签 → 配置
   查看电量轮询间隔
   默认: 360分钟（6小时）
   ```

2. **手动触发读取**
   ```
   设置 → 设备与服务 → BLE 防丢标签
   点击"重新加载"按钮
   等待几秒
   查看电量是否更新
   ```

3. **检查设备支持**
   ```
   查看日志
   搜索: "2a19" 或 "battery"
   如果看到 "设备不支持电量读取"
   说明设备硬件不支持
   ```

4. **验证连接状态**
   ```
   设备必须已连接才能读取电量
   查看连接状态传感器
   ```

## 八、蓝牙网络拓扑诊断（2025.6+）

### 查看网络拓扑

**用途**：诊断蓝牙设备和代理的连接状态

**步骤**：
1. 进入 **设置** → **设备与服务** → **蓝牙**
2. 点击 **配置**
3. 查看 **网络拓扑** 部分

### 诊断检查项

#### 1. 检查设备连接路径

**正常情况**：
```
Home Assistant → ESP-Proxy-1 → 设备
```

**异常情况**：
```
Home Assistant → ✗ 设备（无连接路径）
```

**解决**：
- 靠近设备
- 检查代理是否在线
- 重启代理

#### 2. 检查代理状态

**查看代理列表**：
- 🟢 **在线**：代理正常工作
- 🔴 **离线**：代理未响应
- 🟡 **弱信号**：代理连接不稳定

**代理离线解决**：
1. 检查ESP-Proxy电源
2. 检查ESP-Proxy Wi-Fi连接
3. 重启ESP-Proxy

#### 3. 检查设备状态

**设备状态类型**：
- 🟢 **已连接**：设备正常连接
- 🟡 **在范围内**：设备可发现但未连接
- 🔴 **连接失败**：无法连接设备
- ⚪ **未知**：设备信息不足

**设备离线诊断**：
1. 确认设备已开机
2. 确认设备电量充足
3. 靠近蓝牙适配器或代理
4. 查看详细错误日志

### 网络拓扑常见问题

#### 问题1：设备显示为"在范围内"但未连接

**可能原因**：
- 设备被其他应用占用
- 连接槽位已满
- 设备不支持主动连接

**解决方案**：
```yaml
# 1. 检查连接数限制
设置 → 设备与服务 → BLE 防丢标签
查看已连接设备数量

# 2. 关闭部分设备的"维持连接"
设置 → 设备与服务 → BLE 防丢标签 → 设备 → 配置
维持连接：关闭

# 3. 手动触发连接
设置 → 设备与服务 → BLE 防丢标签
点击"重新加载"
```

#### 问题2：代理显示离线

**诊断步骤**：
```
1. 检查ESP-Proxy电源（LED灯是否亮）
2. 检查ESP-Proxy Wi-Fi连接
   - ESP-Proxy → 配置 → Wi-Fi
3. 检查Home Assistant与ESP-Proxy的网络连接
   - ping ESP-Proxy的IP地址
4. 查看ESP-Proxy日志
   - ESP Home → 设备 → Logs
```

**解决方案**：
```
# 重启ESP-Proxy
ESP Home → 设备 → 重启

# 或通过Web UI重启
访问ESP-Proxy IP地址 → Restart
```

#### 问题3：网络拓扑显示不完整

**可能原因**：
- Home Assistant版本 < 2025.6
- 浏览器缓存问题
- 蓝牙集成未正确配置

**解决方案**：
```
1. 确认Home Assistant版本
   设置 → 系统 → 信息
   版本 ≥ 2025.6

2. 清除浏览器缓存
   Ctrl + Shift + Delete
   清除缓存后刷新

3. 重新加载蓝牙集成
   设置 → 设备与服务 → 蓝牙
   点击"重新加载"
```

### 使用网络拓扑优化布局

#### 场景1：信号覆盖不足

**症状**：
- 部分区域设备离线
- 网络拓扑显示弱信号

**解决方案**：
```
1. 添加ESP-Proxy到信号弱区域
2. 调整现有代理位置（避开障碍物）
3. 增加代理数量覆盖更大范围
```

#### 场景2：连接槽位不足

**症状**：
- 添加新设备时连接失败
- 网络拓扑显示设备在范围内但未连接

**解决方案**：
```
1. 查看当前连接数
   网络拓扑 → 统计连接数

2. 关闭不必要的"维持连接"
   设置 → 设备与服务 → BLE 防丢标签 → 设备 → 配置
   维持连接：关闭

3. 添加更多蓝牙适配器或代理
   - USB适配器：最多3-5个设备
   - ESP-Proxy：最多2-3个设备
```

#### 场景3：代理重叠干扰

**症状**：
- 设备频繁在代理间切换
- 连接不稳定

**解决方案**：
```
1. 查看网络拓扑
   识别代理重叠区域

2. 分离代理位置
   - 保持代理距离 > 5米
   - 避免直线排列

3. 调整广播功率
   ESP Home → 代理配置 → TX Power
   降低功率减少重叠
```

### 网络拓扑最佳实践

#### 1. 定期检查网络拓扑

**频率**：每周一次

**检查项**：
- [ ] 所有代理在线
- [ ] 所有设备已连接
- [ ] 无信号弱区域
- [ ] 无连接失败设备

#### 2. 记录网络拓扑变化

**记录内容**：
- 新增设备
- 新增代理
- 设备位置变更
- 代理位置变更

**记录方法**：
```yaml
# 网络拓扑日志
2025-03-06:
  - 添加ESP-Proxy-3（书房）
  - 设备：钥匙扣移至Proxy-1覆盖范围

2025-03-13:
  - 调整Proxy-2位置（避开路由器干扰）
  - 连接稳定性提升
```

#### 3. 使用网络拓扑规划扩展

**规划步骤**：
```
1. 绘制当前网络拓扑
2. 标识信号弱区域
3. 规划新代理位置
4. 预估设备连接数
5. 实施并验证
```
