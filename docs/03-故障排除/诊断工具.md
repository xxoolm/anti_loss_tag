## 二、Home Assistant内置诊断工具

### 2.1 开发者工具 - 状态

**用途**：查看所有实体的当前状态

**步骤**：
1. 进入 **设置** → **开发者工具**
2. 点击 **状态** 标签
3. 在搜索框中输入您的设备名称

**查看内容**：
- Entity ID
- Friendly Name
- 状态值
- 最后更新时间
- 属性

**示例**：
```
Entity ID: sensor.my_keys_battery
State: 85
Attributes:
  unit_of_measurement: %
  device_class: battery
  friendly_name: 我的钥匙 电量
```

---

### 2.2 开发者工具 - 事件

**用途**：监听和查看实时事件

**步骤**：
1. 进入 **设置** → **开发者工具**
2. 点击 **事件** 标签
3. 在 **监听事件** 中输入事件名称
4. 点击 **开始监听**

**常用事件**：
- `anti_loss_tag_button_event` - 按钮事件
- `state_changed` - 状态变化

**示例事件数据**：
```json
{
  "entity_id": "event.my_keys_button_event",
  "event_type": "单击",
  "raw_data": "01000000000000"
}
```

---

### 2.3 开发者工具 - 模板

**用途**：测试Jinja2模板和表达式

**步骤**：
1. 进入 **设置** → **开发者工具**
2. 点击 **模板** 标签
3. 输入模板表达式
4. 点击 **渲染模板**

**常用模板**：

**查找所有相关实体**：
```jinja2
{% for entity in states.sensor if 'my_keys' in entity.entity_id %}
{{ entity.entity_id }}: {{ entity.state }}
{% endfor %}
```

**获取设备属性**：
```jinja2
{{ state_attr('sensor.my_keys_battery', 'device_class') }}
```

**格式化RSSI值**：
```jinja2
{{ states('sensor.my_keys_rssi') }} dBm
```

---

### 2.4 开发者工具 - 服务

**用途**：手动调用服务进行测试

**步骤**：
1. 进入 **设置** → **开发者工具**
2. 点击 **服务** 标签
3. 选择服务和域
4. 填写服务数据
5. 点击 **调用服务**

**常用服务测试**：

**测试报警功能**：
```
域: anti_loss_tag
服务: trigger_alarm
实体ID: button.my_keys_trigger_alarm
```

**测试通知**：
```
域: notify
服务: mobile_app_my_phone
数据:
  message: "测试通知"
```

---

### 2.5 开发者工具 - YAML配置

**用途**：检查YAML配置语法

**步骤**：
1. 进入 **设置** → **开发者工具**
2. 点击 **YAML** 标签
3. 粘贴YAML配置
4. 检查错误提示

**检查内容**：
- automations.yaml

## 三、日志诊断

### 3.1 查看日志

**步骤**：
1. 进入 **设置** → **系统**
2. 点击 **日志** 标签
3. 选择日志级别：
   - **全部** - 所有日志
   - **调试** - 详细调试信息
   - **信息** - 一般信息
   - **警告** - 警告和错误
   - **错误** - 仅错误

---

### 3.2 搜索关键字

**常用搜索关键字**：

```
anti_loss_tag
bleak
bluetooth
gatt
connection
battery
error
warning
```

**搜索方法**：
1. 在日志页面的搜索框中输入关键字
2. 使用正则表达式：`bleak.*error`
3. 使用多个关键字：`anti_loss_tag.*error`

---

### 3.3 启用调试日志

**临时启用**（重启后失效）：
1. 进入 **设置** → **系统** → **日志**
2. 选择 **调试** 日志级别
3. 重启集成

**永久启用**（修改配置文件）：
```yaml
# configuration.yaml
logger:
  default: info
  logs:
    custom_components.anti_loss_tag: debug
    bleak: debug
    bleak.exc: debug
    bluetooth_adapters: debug
```

**重启后生效**：
```
设置 → 系统 → 服务器管理 → 重启
```

---

## 四、系统诊断

### 4.1 检查蓝牙适配器

**方法1：通过UI**
```
设置 → 系统 → 硬件
查看"蓝牙"部分
```

**方法2：通过命令行**（SSH）：
```bash
# Linux
hciconfig -a

# 应该看到类似输出：
# hci0:	Type: Primary  Bus: USB
# 	BD Address: XX:XX:XX:XX:XX:XX  ACL MTU: 1021:8  SCO MTU: 64:1
# 	UP RUNNING 
```

---

### 4.2 检查BLE扫描

**方法1：通过集成**
```
设置 → 设备与服务 → BLE 防丢标签
点击"添加集成"
查看扫描列表
```

**方法2：通过命令行**（SSH）：
```bash
# 使用bluetoothctl
bluetoothctl
scan on
# 查看是否能扫描到设备
scan off
exit
```

---

### 4.3 检查资源使用

**方法1：通过UI**
```
设置 → 系统 → 服务器管理
查看CPU、内存、磁盘使用情况
```

**方法2：通过命令行**（SSH）：
```bash
# 查看CPU和内存
top -bn1 | head -20

# 查看磁盘使用
df -h

# 查看进程
ps aux | grep homeassistant
```

## 五、常见问题诊断流程

### 问题1：扫描不到设备

**诊断流程**：

1. **检查设备状态**
   ```
   设备是否开机？
   设备电量是否充足？
   设备是否在范围内（< 5米）？
   ```

2. **检查蓝牙适配器**
   ```
   设置 → 系统 → 硬件
   查看蓝牙是否检测到
   ```

3. **查看日志**
   ```
   设置 → 系统 → 日志
   搜索: "scanner" 或 "bluetooth"
   ```

4. **手动扫描测试**
   ```bash
   bluetoothctl
   scan on
   # 查看设备是否出现在列表中
   ```

---

### 问题2：连接失败

**诊断流程**：

1. **检查设备是否被占用**
   ```
   关闭手机蓝牙
   卸载手机上的防丢标签App
   重试连接
   ```

2. **检查信号强度**
   ```
   将设备靠近（< 0.5米）
   避开金属障碍物
   ```

3. **查看详细日志**
   ```
   启用调试日志
   设置 → 系统 → 日志
   搜索: "connection" 或 "gatt"
   ```

4. **分析错误原因**
   ```
   常见错误：
   - "Device not found" - 设备未发现
   - "Connection timeout" - 连接超时
   - "GATT error" - GATT操作失败
   ```

---

### 问题3：按钮事件不触发

**诊断流程**：

1. **确认设备已连接**
   ```
   查看连接状态传感器
   应该显示 "on"
   ```

2. **确认通知已开启**
   ```
   查看日志
   搜索: "notify" 或 "FFE1"
   应该看到 "FFE1 通知已开启"
   ```

3. **使用事件监听器**
   ```
   设置 → 开发者工具 → 事件
   监听: anti_loss_tag_button_event
   按下设备按钮
   查看是否有事件
   ```

4. **创建调试自动化**
   ```yaml
   automation:
     - alias: "调试按钮事件"
       trigger:
         - platform: event
           event_type: anti_loss_tag_button_event
       action:
         - service: logger.log
           data:
             message: "按钮事件: {{ trigger.event.data }}"
   ```

---

### 问题4：电量不更新

**诊断流程**：

1. **确认轮询间隔**
   ```
   设置 → 设备与服务 → BLE 防丢标签 → 配置
   查看电量轮询间隔
   默认: 360分钟（6小时）
   ```

2. **手动触发读取**
   ```
   设置 → 设备与服务 → BLE 防丢标签
   点击"重新加载"按钮
   等待几秒
   查看电量是否更新
   ```

3. **检查设备支持**
   ```
   查看日志
   搜索: "2a19" 或 "battery"
   如果看到 "设备不支持电量读取"
   说明设备硬件不支持
   ```

4. **验证连接状态**
   ```
   设备必须已连接才能读取电量
   查看连接状态传感器
   ```

## 六、高级诊断

### 6.1 使用GDB调试（仅限开发者）

**不推荐普通用户使用**

```bash
# 找到Home Assistant进程
ps aux | grep python

# 附加GDB
sudo gdb -p <PID>

# 设置断点
(gdb) break custom_components.anti_loss_tag.device:connect

# 继续执行
(gdb) continue

# 查看堆栈
(gdb) bt
```

---

### 6.2 使用Wireshark抓包

**用途**：分析BLE通信数据包

**步骤**：
1. 安装Wireshark
2. 选择蓝牙适配器接口
3. 开始抓包
4. 操作设备
5. 停止抓包
6. 分析数据包

**过滤器**：
```
btle.address == AA:BB:CC:DD:EE:FF
btatt
```

---

### 6.3 使用bleak调试工具

**Python脚本**：
```python
import asyncio
from bleak import BleakClient

async def debug_device(address):
    async with BleakClient(address) as client:
        # 服务发现
        services = client.services
        for service in services:
            print(f"Service: {service.uuid}")
            for char in service.characteristics:
                print(f"  Characteristic: {char.uuid}")
                print(f"    Properties: {char.properties}")

asyncio.run(debug_device("AA:BB:CC:DD:EE:FF"))
```

## 七、诊断检查清单

### 安装检查
- [ ] 集成已安装到正确位置
- [ ] manifest.json格式正确
- [ ] Home Assistant已重启
- [ ] 日志中无启动错误

### 连接检查
- [ ] 蓝牙适配器已启用
- [ ] 设备在扫描范围内
- [ ] 设备未被其他应用占用
- [ ] 设备电量充足

### 功能检查
- [ ] 连接状态传感器正常
- [ ] 电量传感器正常（如果支持）
- [ ] RSSI传感器正常
- [ ] 按钮事件正常（如果支持）
- [ ] 报警功能正常（如果支持）

### 配置检查
- [ ] 所有配置参数已应用
- [ ] 轮询间隔合理
- [ ] 勿扰时段已设置（如果需要）
- [ ] 维持连接设置正确
