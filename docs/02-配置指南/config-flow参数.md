# Config Flow 配置参数详解

> **配置流程中的所有参数说明**
> 
> **目标读者**：用户 + 开发者  
**用途**：理解每个配置选项的作用和影响

---

## 一、基本配置

### 1.1 设备名称

**参数名**：`device_name`  
**类型**：字符串  
**默认值**：自动生成（基于MAC地址）  
**必填**：否

**说明**：
- 设备在 Home Assistant 中的显示名称
- 可以随时修改，不影响设备功能
- 建议使用易识别的名称（如"钥匙扣"、"钱包"等）

**示例**：
```
钥匙扣
钱包
车钥匙
宠物标签
```

---

### 1.2 维持连接

**参数名**：`maintain_connection`  
**类型**：布尔值  
**默认值**：`false`（关闭）  
**必填**：否

**说明**：
- 控制是否保持常驻 BLE 连接
- 开启后，设备将始终保持连接状态
- 关闭后，只在需要时才连接（如触发报警）

**⚠️ 重要建议**：建议**关闭**此选项

**原因**：
1. **省电**：常驻连接会增加设备耗电
2. **稳定性**：蓝牙连接可能因距离或干扰断开，导致频繁重连
3. **功能完整**：即使关闭维持连接，所有功能仍可正常使用

**何时应该开启**：
- 需要实时监控按钮事件（延迟要求极低）
- 需要频繁读取电量或RSSI
- 设备距离 Home Assistant 很近（< 2米）

**何时应该关闭**（推荐）：
- 日常使用场景
- 设备可能在 Home Assistant 范围外
- 关注电池续航

## 二、轮询配置

### 2.1 电量轮询间隔

**参数名**：`battery_poll_interval_min`  
**类型**：整数（分钟）  
**默认值**：`360`（6小时）  
**范围**：5 - 10080 分钟（5分钟到7天）

**说明**：
- 控制读取设备电量的频率
- 只在设备已连接时才会读取
- 越频繁耗电越多，但数据更新更及时

**推荐值**：
- **日常使用**：360分钟（6小时）或更长
- **测试调试**：10-30分钟
- **低电量设备**：720分钟（12小时）或更长

**注意事项**：
- ⚠️ 设置过短（< 30分钟）会显著增加设备耗电
- ⚠️ 设置过长（> 1440分钟）可能导致电量信息不及时
- ✅ 设备低电量时会自动减少轮询频率

**计算示例**：
```
10分钟间隔 → 每天读取 144 次 → 耗电高
60分钟间隔 → 每天读取 24 次 → 中等
360分钟间隔 → 每天读取 4 次 → 低耗电
1440分钟间隔 → 每天读取 1 次 → 最低耗电
```

---

### 2.2 RSSI 轮询间隔

**参数名**：`rssi_poll_interval_min`  
**类型**：整数（分钟）  
**默认值**：`10`（10分钟）  
**范围**：1 - 60 分钟

**说明**：
- 控制读取设备信号强度（RSSI）的频率
- RSSI 用于判断设备距离
- 只在设备已连接时才会读取

**推荐值**：
- **日常使用**：10分钟（默认值）
- **距离监控**：5分钟
- **低功耗模式**：15-30分钟

**RSSI 值参考**：
```
-50 到 -40 dBm：非常好（非常近，< 1米）
-60 到 -50 dBm：良好（近距离，1-5米）
-70 到 -60 dBm：一般（中等距离，5-10米）
-80 到 -70 dBm：差（远距离，10-20米）
< -80 dBm：不可用（可能断开）
```

**注意事项**：
- ⚠️ RSSI 波动较大，单次读数可能不准确
- ⚠️ 频繁读取会增加设备耗电
- ✅ 可以基于 RSSI 设置自动化（如距离过远时通知）

## 三、报警配置

### 3.1 断开报警

**参数名**：`alarm_on_disconnect`  
**类型**：布尔值  
**默认值**：`false`（关闭）  
**必填**：否

**说明**：
- 控制设备断开连接时是否触发报警
- 开启后，断开连接会写入 2a06 触发设备报警
- 报警会持续直到：
  - 设备重新连接
  - 用户手动取消
  - 超过报警超时时间（设备固件决定）

**使用场景**：
- ✅ 防止物品丢失（离开范围时报警）
- ✅ 防止儿童走失（超出范围时提醒）
- ❌ 不适合频繁进出范围的场景（会导致频繁误报）

**工作流程**：
```
1. 设备连接 → 正常状态
2. 设备断开连接
3. 检查"断开报警"开关
4. 检查勿扰条件
5. 满足条件 → 写入 2a06 (0x01) → 设备报警
6. 启动重连任务
```

**注意事项**：
- ⚠️ 报警依赖设备支持 2a06 特征
- ⚠️ 如果设备不支持 2a06，断开报警功能不可用
- ⚠️ 报警会消耗设备电量

---

### 3.2 勿扰时段

**参数名**：`do_not_disturb_time`  
**类型**：字符串（时间范围）  
**默认值**：无（空）  
**格式**：`HH:MM-HH:MM`（24小时制）

**说明**：
- 在指定时间段内，禁用断开报警
- 适用于睡眠时间等场景
- 不影响其他功能（按钮事件、电量读取等）

**示例**：
```
22:00-08:00  # 晚上10点到早上8点勿扰
23:00-07:00  # 晚上11点到早上7点勿扰
```

**注意事项**：
- ⚠️ 时间范围不能超过24小时
- ⚠️ 结束时间必须晚于开始时间（跨天需要分段设置）
- ✅ 在勿扰时段内，断开连接不会触发报警

**跨天设置**：
```
# 如果需要 22:00 到次日 08:00 勿扰
# 可以分段设置：
22:00-23:59
00:00-08:00
```

---

### 3.3 勿扰 Wi-Fi

**参数名**：`do_not_disturb_wifi`  
**类型**：字符串（Wi-Fi SSID）  
**默认值**：无（空）  
**必填**：否

**说明**：
- 当连接到指定 Wi-Fi 时，禁用断开报警
- 适用于回家后自动禁用报警的场景
- 检测的是 Home Assistant 所在设备的 Wi-Fi 连接

**示例**：
```
MyHomeWiFi
家庭网络
Office_5G
```

**使用场景**：
- ✅ 回家后自动禁用报警（在安全范围内）
- ✅ 在办公室时禁用报警
- ✅ 避免在安全范围内频繁误报

**注意事项**：
- ⚠️ Wi-Fi 名称必须完全匹配（区分大小写）
- ⚠️ 只检测 Home Assistant 的 Wi-Fi，不是防丢标签的
- ✅ 与勿扰时段可以同时使用

## 四、高级配置

### 4.1 连接超时

**参数名**：`connection_timeout_sec`  
**类型**：整数（秒）  
**默认值**：`20`  
**范围**：10 - 60 秒

**说明**：
- 尝试连接设备的超时时间
- 如果连接时间超过此值，将视为连接失败
- ESPHome 代理建议设置为 20 秒

**推荐值**：
- **USB 适配器**：10-20秒
- **ESPHome 代理**：20秒（默认值）
- **不稳定环境**：30-60秒

**注意事项**：
- ⚠️ 设置过短可能导致连接失败
- ⚠️ 设置过长会延长错误检测时间
- ✅ 大多数情况下不需要修改默认值

---

### 4.2 最大重连次数

**参数名**：`max_reconnect_attempts`  
**类型**：整数  
**默认值**：`0`（无限重连）  
**范围**：0（无限）或正整数

**说明**：
- 控制断开后自动重连的最大次数
- 设置为 0 表示无限重连（默认）
- 达到最大次数后停止重连

**推荐值**：
- **日常使用**：0（无限重连）
- **临时使用**：10-20次
- **测试调试**：3-5次

**注意事项**：
- ⚠️ 设置过小可能导致设备永久离线
- ⚠️ 无限重连会持续尝试连接，但不会影响其他设备
- ✅ 可以通过"重新加载"按钮重置重连计数

---

### 4.3 重连延迟

**参数名**：`reconnect_delay_sec`  
**类型**：整数（秒）  
**默认值**：`5`  
**范围**：1 - 60 秒

**说明**：
- 每次重连尝试之间的延迟
- 使用指数退避策略（每次失败后延迟加倍）
- 最大延迟不超过此值

**退避策略示例**：
```
初始延迟：5秒
第1次失败：等待 5秒
第2次失败：等待 10秒（5×2）
第3次失败：等待 20秒（10×2）
第4次失败：等待 40秒（20×2）
...
最大延迟：60秒（由 reconnect_delay_sec 限制）
```

**推荐值**：
- **日常使用**：5秒（默认值）
- **不稳定环境**：10-15秒
- **快速重连**：2-3秒

**注意事项**：
- ⚠️ 设置过短可能造成"连接风暴"
- ⚠️ 设置过长会延长恢复时间
- ✅ 大多数情况下不需要修改默认值

## 五、参数组合示例

### 场景1：日常使用（推荐）

```yaml
maintain_connection: false          # 关闭常驻连接
battery_poll_interval_min: 360      # 6小时更新电量
rssi_poll_interval_min: 10          # 10分钟更新RSSI
alarm_on_disconnect: true           # 开启断开报警
do_not_disturb_time: "22:00-08:00"  # 晚上勿扰
do_not_disturb_wifi: "MyHomeWiFi"   # 回家勿扰
```

**适用**：防止物品丢失，日常携带

---

### 场景2：低功耗模式

```yaml
maintain_connection: false          # 关闭常驻连接
battery_poll_interval_min: 720      # 12小时更新电量
rssi_poll_interval_min: 30          # 30分钟更新RSSI
alarm_on_disconnect: false          # 关闭断开报警
do_not_disturb_time: ""             # 无勿扰时段
do_not_disturb_wifi: ""             # 无勿扰Wi-Fi
```

**适用**：电池续航优先，简单监控

---

### 场景3：实时监控（测试用）

```yaml
maintain_connection: true           # 开启常驻连接
battery_poll_interval_min: 30       # 30分钟更新电量
rssi_poll_interval_min: 5           # 5分钟更新RSSI
alarm_on_disconnect: true           # 开启断开报警
do_not_disturb_time: ""             # 无勿扰时段
do_not_disturb_wifi: ""             # 无勿扰Wi-Fi
connection_timeout_sec: 15          # 缩短超时
reconnect_delay_sec: 3              # 快速重连
```

**适用**：开发调试，实时监控

## 六、配置修改

### 通过界面修改

1. 进入 **设置** → **设备与服务**
2. 找到 **BLE 防丢标签** 集成
3. 点击 **配置**
4. 修改配置选项
5. 点击 **提交**
6. 等待配置生效

### 通过 YAML 修改（不推荐）

⚠️ **不推荐**通过 `configuration.yaml` 修改配置，因为：
- Config Flow 是标准的配置方式
- YAML 配置可能被界面覆盖
- 难以验证配置正确性

**如果必须使用 YAML**：
```yaml
# configuration.yaml
anti_loss_tag:
  devices:
    - mac_address: "AA:BB:CC:DD:EE:FF"
      name: "钥匙扣"
      maintain_connection: false
      battery_poll_interval_min: 360
```

## 七、配置验证

### 检查配置是否生效

**方法1：查看设备状态**
```
设置 → 设备与服务 → BLE 防丢标签 → 设备
```
- 检查实体是否按预期更新
- 检查连接状态是否正常

**方法2：查看日志**
```
设置 → 系统 → 日志
```
- 搜索 "anti_loss_tag"
- 查看配置加载日志
- 确认无错误或警告

**方法3：测试功能**
- 触发按钮，检查是否收到事件
- 远离设备，检查是否触发报警
- 等待轮询间隔，检查数据是否更新

## 八、常见配置问题

### Q1: 修改配置后没有生效？

**A**: 检查以下几点：
1. ✅ 是否点击了"提交"？
2. ✅ 是否等待了配置生效？
3. ✅ 查看日志是否有错误？
4. ✅ 尝试"重新加载"集成

### Q2: 断开报警频繁误报？

**A**: 调整以下配置：
1. 启用勿扰时段
2. 启用勿扰 Wi-Fi
3. 检查蓝牙信号是否稳定
4. 考虑关闭断开报警

### Q3: 电量更新太慢？

**A**: 调整配置：
1. 缩短 `battery_poll_interval_min`
2. 或手动触发电量读取（按钮实体）

### Q4: 设备频繁断开重连？

**A**: 检查：
1. 蓝牙信号是否稳定（查看RSSI）
2. 设备是否在覆盖范围边缘
3. 是否有其他蓝牙设备干扰
4. 考虑使用 ESPHome 代理扩展范围
