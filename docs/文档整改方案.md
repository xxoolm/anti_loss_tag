## 八、蓝牙网络拓扑（2025.6+新功能）

### 什么是网络拓扑？

**网络拓扑**显示所有蓝牙设备的连接关系：
- **设备图标**：显示所有已发现的设备
- **连接线**：显示设备与Home Assistant的连接路径
- **代理标识**：显示设备通过哪个代理连接

### 如何查看网络拓扑

**步骤**：
1. 进入 **设置** → **设备与服务**
2. 找到 **蓝牙** 集成
3. 点击 **配置**
4. 在 **网络拓扑** 部分查看：
   - 🟢 绿色 = 已连接设备
   - 🟡 黄色 = 在范围内但未连接
   - 🔴 红色 = 连接失败

### 网络拓扑用途

**1. 诊断连接问题**
- 查看设备是否在范围内
- 确认设备通过哪个代理连接
- 识别信号弱设备

**2. 优化蓝牙布局**
- 调整代理位置
- 添加更多代理
- 避免代理重叠

**3. 验证设备状态**
- 实时查看设备连接状态
- 识别离线设备
- 排查连接失败原因

### 网络拓扑示例

```
Home Assistant
    │
    ├── 🟢 ESP-Proxy-1 (客厅)
    │      ├── 🟢 钥匙扣 (直接连接)
    │      ├── 🟢 钱包 (通过代理)
    │      └── 🟡 车钥匙 (在范围内)
    │
    ├── 🟢 ESP-Proxy-2 (卧室)
    │      ├── 🟢 宠物标签
    │      └── 🔴 旧标签 (连接失败)
    │
    └── 🟢 内置适配器
           └── 🟢 测试设备
```

**版本要求**：
- Home Assistant ≥ 2025.6
- 蓝牙集成已配置

**如果没有看到网络拓扑**：
- 确认Home Assistant版本 ≥ 2025.6
- 等待几秒钟让拓扑加载
- 刷新浏览器页面

**异常情况**：

Home Assistant → ✗ 设备（无连接路径）

**查看代理列表**：

- 🟢 **已连接**：设备正常连接
- 🟡 **在范围内**：设备可发现但未连接
- 🔴 **连接失败**：无法连接设备

设置 → 设备与服务 → BLE 防丢标签 → 设备 → 配置
维持连接：关闭

# 3. 手动触发连接
设置 → 设备与服务 → BLE 防丢标签
点击"重新加载"
```

#### 问题2：代理显示离线

**诊断步骤**：
```
1. 检查ESP-Proxy电源（LED灯是否亮）
2. 检查ESP-Proxy Wi-Fi连接
   - ESP-Proxy → 配置 → Wi-Fi
3. 检查Home Assistant与ESP-Proxy的网络连接
   - ping ESP-Proxy的IP地址
4. 查看ESP-Proxy日志
   - ESP Home → 设备 → Logs
```

**解决方案**：
```
# 重启ESP-Proxy
ESP Home → 设备 → 重启

# 或通过Web UI重启
访问ESP-Proxy IP地址 → Restart
```

### 使用网络拓扑优化布局

#### 场景1：信号覆盖不足

**症状**：
- 部分区域设备离线
- 网络拓扑显示弱信号

**解决方案**：
```
1. 添加ESP-Proxy到信号弱区域
2. 调整现有代理位置（避开障碍物）
3. 增加代理数量覆盖更大范围
```

#### 场景2：连接槽位不足

**症状**：
- 添加新设备时连接失败
- 网络拓扑显示设备在范围内但未连接

**解决方案**：
```
1. 查看当前连接数
   网络拓扑 → 统计连接数

2. 关闭不必要的"维持连接"
   设置 → 设备与服务 → BLE 防丢标签 → 设备 → 配置
   维持连接：关闭

3. 添加更多蓝牙适配器或代理
   - USB适配器：最多3-5个设备
   - ESP-Proxy：最多2-3个设备
```

#### 场景3：代理重叠干扰

**症状**：
- 设备频繁在代理间切换
- 连接不稳定

**解决方案**：
```
1. 查看网络拓扑
   识别代理重叠区域

2. 分离代理位置
   - 保持代理距离 > 5米
   - 避免直线排列

3. 调整广播功率
   ESP Home → 代理配置 → TX Power
   降低功率减少重叠
```

### 问题2：蓝牙适配器权限问题（Container）

**影响版本**：
- Home Assistant Container
- Linux系统

**症状**：
- 添加集成时提示"蓝牙适配器未就绪"
- 日志显示"Permission denied"访问蓝牙设备

**原因**：
Home Assistant容器用户没有访问蓝牙设备的权限。

**解决方案**：

**检查权限**：
```bash
# 进入容器
docker exec -it home-assistant bash

# 检查蓝牙设备
ls -la /dev/bus/usb/

# 检查用户组
id
```

**添加权限**：

**方法1：添加设备映射**
```yaml
# docker-compose.yml
services:
  home-assistant:
    devices:
      - /dev/bus/usb:/dev/bus/usb
      - /dev/ttyACM0:/dev/ttyACM0
```

**方法2：添加用户到组**
```bash
# 查看蓝牙设备组
ls -la /dev/bus/usb/001/

# 添加用户到组（假设组名为usb）
sudo usermod -a -G usb $(id -u)
```

**方法3：使用--privileged（不推荐）**
```bash
docker run --privileged home-assistant
```

**重启容器**：
```bash
docker restart home-assistant
```

**验证**：
```
设置 → 系统 → 硬件
查看蓝牙适配器是否显示
```

### 问题3：2025.3.x蓝牙配置问题

**影响版本**：
- Home Assistant 2025.3.0 - 2025.3.2
- 特定配置格式

**症状**：
- configuration.yaml中的蓝牙配置报错
- 集成加载失败

**原因**：
2025.3.x引入了新的蓝牙配置格式验证。

**解决方案**：

**旧配置（不再支持）**：
```yaml
# ❌ 2025.3.x之前
bluetooth:
  adapter: hci0
```

# Linux

# Linux

### 问题5：多个设备连接失败

**影响版本**：
- 所有版本
- 连接设备超过3-5个

**症状**：
- 添加第4个设备时连接失败
- 日志显示"连接槽位不足"

**原因**：
ESP-Proxy和USB适配器有连接数限制。

**解决方案**：

**检查当前连接数**：
```yaml
# 使用开发者工具
设置 → 开发者工具 → 模板

模板：
{{ states('sensor.bluetooth_adapters_adapter_connected_devices') }}

或查看网络拓扑：
设置 → 设备与服务 → 蓝牙 → 配置
查看网络拓扑 → 连接数统计
```

**连接数限制**：
```
ESP-Proxy: 2-3个并发连接
USB适配器: 5-8个设备（取决于硬件）
内置适配器: 通常3-5个设备
```

**优化方案**：

**方案1：关闭"维持连接"**
```
设置 → 设备与服务 → BLE 防丢标签 → 设备 → 配置
维持连接：关闭 ⛔

优点：减少并发连接
缺点：按钮事件延迟增加
```

**方案2：增加适配器**
```
添加更多蓝牙适配器：
- USB适配器（最多3-5个）
- ESP-Proxy（最多2-3个设备）

配置：
设置 → 设备与服务 → 蓝牙 → 配置
添加适配器
```

**方案3：使用多个ESP-Proxy**
```
1. 部署多个ESP-Proxy
2. 分散设备连接
3. 避免单个代理过载

布局示例：
- ESP-Proxy-1（客厅）：2-3个设备
- ESP-Proxy-2（卧室）：2-3个设备
- 内置适配器：1-2个设备
```

**方案4：调整轮询间隔**
```
降低轮询频率减少连接时间：

电量轮询：360分钟 → 720分钟
RSSI轮询：10分钟 → 30分钟
```

**验证优化效果**：
```
1. 查看网络拓扑
   连接数应 ≤ 限制

2. 查看日志
   应该减少"连接槽位不足"错误

3. 测试所有设备
   确认所有设备能正常连接
```

### 问题6：蓝牙信号弱或不稳定

**影响版本**：
- 所有版本
- 特定环境

**症状**：
- 设备频繁断开
- RSSI值低于-80dBm
- 连接状态不稳定

**诊断**：

**查看信号强度**：
```
设置 → 设备与服务 → BLE 防丢标签
查看 RSSI 传感器

信号判断：
- -50 到 -40 dBm：非常好（< 1米）
- -60 到 -50 dBm：良好（1-5米）
- -70 到 -60 dBm：一般（5-10米）
- -80 到 -70 dBm：差（10-20米）
< -80 dBm：不可用
```

**解决方案**：

**方案1：优化适配器位置**
```
1. 将适配器放置在中心位置
2. 避开金属物体
3. 远离干扰源（路由器、微波炉）
4. 使用USB延长线调整位置
```

**方案2：使用ESP-Proxy扩展**
```
1. 在信号弱区域添加ESP-Proxy
2. ESP-Proxy通过Wi-Fi连接到HA
3. 设备连接到附近的ESP-Proxy

优点：
- 扩大覆盖范围
- 减少单个适配器负载
- 提高连接稳定性
```

**方案3：调整广播功率**
```
ESP Home → ESP-Proxy配置
TX Power: +6dBm（提高功率）

注意：
- 功率越高，功耗越大
- 可能增加干扰
```

**方案4：优化Wi-Fi信道**
```
2.4GHz Wi-Fi和蓝牙使用相同频段

Wi-Fi信道建议：
- 使用信道1、6、11（避免重叠）
- 远离蓝牙设备
- 使用5GHz Wi-Fi（如果可能）
```

**环境优化检查清单**：
- [ ] 适配器位置居中
- [ ] 避开金属物体
- [ ] 远离干扰源
- [ ] 使用ESP-Proxy扩展
- [ ] 优化Wi-Fi信道
- [ ] 调整设备轮询间隔

## 一、蓝牙适配器状态监控

### 1.1 适配器状态实体

**实体列表**：

| Entity ID | 说明 | 更新频率 |
|-----------|------|----------|
| `sensor.bluetooth_adapter_connected_devices` | 已连接设备数 | 实时 |
| `sensor.bluetooth_adapter_active_connections` | 活跃连接数 | 实时 |
| `sensor.bluetooth_adapter_scanning` | 是否正在扫描 | 实时 |
| `sensor.bluetooth_adapter_last_seen` | 最后发现时间 | 实时 |

**查看方法**：
```
设置 → 开发者工具 → 状态
搜索: "bluetooth_adapter"
```

### 1.2 适配器健康指标

**指标说明**：

**1. 连接健康度**
```
计算公式：(活跃连接数 / 最大连接数) * 100%

健康判断：
- < 50%: 健康 ✅
- 50-80%: 良好 ⚠️
- > 80%: 拥挤 ❌
```

**2. 扫描效率**
```
计算：(发现的设备数 / 扫描时间)

正常值：
- > 1 设备/秒: 高效 ✅
- 0.5-1 设备/秒: 正常 ⚠️
- < 0.5 设备/秒: 低效 ❌
```

**3. 连接成功率**
```
计算：(成功连接数 / 尝试连接数) * 100%

要求：
- > 90%: 良好 ✅
- 70-90%: 一般 ⚠️
- < 70%: 需要优化 ❌
```
