## 二、开始之前

### 2.1 检查现有Issue

1. 访问 [GitHub Issues](https://github.com/xxoolm/anti_loss_tag/issues)
2. 搜索是否有相关问题
3. 如果没有，创建新Issue描述问题或功能请求

### 2.2 讨论方案

对于重大变更：
- 在Issue中讨论方案
- 等待维护者反馈
- 达成共识后再开始开发

## 三、开发流程

### 3.1 Fork仓库

1. 访问 [GitHub仓库](https://github.com/xxoolm/anti_loss_tag)
2. 点击右上角 **Fork** 按钮
3. 克隆你的Fork：
   ```bash
   git clone https://github.com/你的用户名/anti_loss_tag.git
   cd anti_loss_tag
   ```

### 3.2 创建分支

```bash
# 添加上游仓库
git remote add upstream https://github.com/xxoolm/anti_loss_tag.git

# 更新主分支
git fetch upstream
git checkout main
git merge upstream/main

# 创建功能分支
git checkout -b feature/your-feature-name
```

**分支命名规范**：
- `feature/功能名称` - 新功能
- `bugfix/问题描述` - Bug修复
- `hotfix/紧急修复` - 紧急修复
- `docs/文档说明` - 文档更新

---

### 3.3 开发和测试

**1. 编写代码**：
- 遵循[代码规范](./代码规范.md)
- 添加类型注解
- 添加文档字符串
- 添加注释

**2. 编写测试**：
- 单元测试覆盖新功能
- 集成测试覆盖关键流程
- 确保测试通过

**3. 运行检查**：
```bash
# 代码检查
ruff check custom_components/anti_loss_tag/

# 自动修复
ruff check --fix custom_components/anti_loss_tag/

# 格式化
ruff format custom_components/anti_loss_tag/

# 类型检查
mypy custom_components/anti_loss_tag/

# 运行测试
pytest tests/ -v

# 带覆盖率
pytest tests/ --cov=custom_components.anti_loss_tag
```

**4. 本地测试**：
- 在Home Assistant中测试
- 验证功能正常工作
- 检查日志无错误

---

### 3.4 提交代码

**Commit消息规范**（Conventional Commits）：
```
<type>(<scope>): <subject>

<body>

<footer>
```

**类型（type）**：
- `feat`：新功能
- `fix`：Bug修复
- `docs`：文档更新
- `style`：代码格式
- `refactor`：重构
- `perf`：性能优化
- `test`：测试
- `chore`：构建/工具

**示例**：
```bash
# 新功能
git commit -m "feat(device): 添加电量读取功能

- 实现电量读取方法
- 添加电量传感器
- 更新文档"

# Bug修复
git commit -m "fix(connection): 修复重连失败问题

- 修复重连时锁未释放
- 添加连接状态检查
- 添加错误日志"

# 文档更新
git commit -m "docs(readme): 更新安装说明

- 添加HACS安装步骤
- 更新依赖版本
- 添加故障排除链接"
```

---

### 3.5 推送到Fork

```bash
# 推送分支
git push origin feature/your-feature-name
```

## 四、创建Pull Request

### 4.1 创建PR

1. 访问你的Fork页面
2. 点击 **Compare & pull request**
3. 填写PR模板

### 4.2 PR模板

```markdown
## 描述
简要描述此PR的目的和内容。

## 类型
- [ ] Bug修复
- [ ] 新功能
- [ ] 代码重构
- [ ] 文档更新
- [ ] 性能优化

## 测试
- [ ] 单元测试通过
- [ ] 集成测试通过
- [ ] 本地测试通过

## 检查清单
- [ ] 代码遵循[代码规范](./代码规范.md)
- [ ] 已添加/更新文档
- [ ] 已添加/更新测试
- [ ] 所有测试通过
- [ ] 无新的警告

## 相关Issue
Closes #issue_number
```

---

### 4.3 PR审查

**维护者会检查**：
- 代码质量
- 测试覆盖
- 文档完整性
- 向后兼容性
- 安全问题

**可能要求**：
- 修改代码
- 添加测试
- 更新文档
- 解决冲突

## 六、合并流程

### 6.1 合并条件

PR必须满足：
- ✅ 所有测试通过
- ✅ 代码审查通过
- ✅ 无合并冲突
- ✅ 文档完整

### 6.2 合并方式

- **Squash and merge**：将所有提交合并为一个
- **Merge commit**：保留所有提交历史
- **Rebase and merge**：线性历史

**推荐**：Squash and merge

---

## 七、发布流程

### 7.1 版本号

遵循语义化版本（Semantic Versioning）：
- **MAJOR.MINOR.PATCH**
  - MAJOR：不兼容的API变更
  - MINOR：向后兼容的功能新增
  - PATCH：向后兼容的Bug修复

**示例**：
- `2.0.3` → `2.0.4`：Bug修复
- `2.0.4` → `2.1.0`：新功能
- `2.1.0` → `3.0.0`：重大变更

---

### 7.2 发布检查清单

**发布前必须完成**：
- [ ] 更新 `manifest.json` 版本号
- [ ] 更新 `pyproject.toml` 版本号
- [ ] 创建 Git tag
- [ ] 更新 CHANGELOG.md
- [ ] 运行完整测试套件
- [ ] 检查文档完整性
- [ ] 验证所有示例代码

**检查命令**：
```bash
# 确认版本号
cat custom_components/anti_loss_tag/manifest.json | grep version
cat pyproject.toml | grep version

# 确认tag
git tag --list "v*" | sort -V | tail -1

# 运行测试
pytest tests/ -v

# 代码检查
ruff check custom_components/anti_loss_tag/
mypy custom_components/anti_loss_tag/
```

---

### 7.3 创建Release

**GitHub Release**：
1. 进入 **Releases** 页面
2. 点击 **Draft a new release**
3. 填写信息：
   - **Tag version**：v2.0.3
   - **Release title**：v2.0.3
   - **Description**：变更内容
4. 点击 **Publish release**

## 十一、快速参考

### 贡献流程总结

```
1. Fork仓库
   ↓
2. 创建分支 (git checkout -b feature/xxx)
   ↓
3. 开发和测试
   ↓

   ↓
6. 创建PR
   ↓
7. 代码审查
   ↓

```
