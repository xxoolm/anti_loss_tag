# 依赖管理指南

> **管理 Home Assistant 自定义集成的依赖**  
> **避免版本冲突，确保兼容性**  
> **目标**：可重现的构建，稳定的运行环境

---

## 一、依赖声明

### 1.1 manifest.json 中的 requirements

```json
{
  "domain": "anti_loss_tag",
  "name": "Anti Loss Tag",
  "requirements": [
    "bleak>=2.1.0,<3.0.0",
    "bleak-retry-connector>=3.8.0",
    "voluptuous>=0.13.1"
  ],
  "version": "1.6.8"
}
```

### 1.2 版本约束最佳实践

| 约束类型 | 示例 | 说明 | 推荐场景 |
|---------|------|------|---------|
| 精确版本 | `==2.1.0` | 锁定到特定版本 | **不推荐**（阻止bug修复） |
| 最低版本 | `>=2.1.0` | 允许新版本 | **推荐**（获取修复） |
| 版本范围 | `>=2.1.0,<3.0.0` | 限制主版本 | **强烈推荐**（API兼容） |
| 兼容版本 | `~=2.1.0` | 等同于 `>=2.1.0,<2.2.0` | **推荐**（语义化版本） |

---

### 1.3 依赖版本矩阵

| 依赖名 | 最低版本 | 推荐版本 | 最大版本 | 备注 |
|--------|---------|---------|---------|------|
| bleak | 2.1.0 | 2.1.1 | <3.0.0 | 2.0.0有start_notify回归 |
| bleak-retry-connector | 3.8.0 | 3.8.1 | - | 频繁更新，测试后再升级 |
| habluetooth | 5.0.0 | 5.x | - | HA蓝牙适配器包装 |
| bleak-esphome | - | latest | - | ESPHome设备支持（可选） |
| voluptuous | 0.13.1 | 0.13.1 | - | 配置验证 |

## 二、常见依赖冲突

### 2.1 bleak 版本冲突案例

#### 场景：多个集成要求不同的 bleak 版本

```
错误：
renogy-ble==1.0.0 要求 bleak==1.0.1
my_integration 要求 bleak>=2.1.0
```

#### 解决方案

**方案1：等待依赖更新**
```bash
# 检查是否有新版本支持
pip index versions renogy-ble
```

**方案2：使用 pip 的依赖解析**
```bash
# 尝试自动解决冲突
pip install --upgrade --force-reinstall bleak
```

**方案3：手动降级/升级**
```bash
# 创建虚拟环境隔离
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

---

### 2.2 pydantic 版本冲突

#### 问题
- Home Assistant 2025.5.2 使用 `pydantic==2.11.3`
- 某些自定义集成要求 `pydantic >=2.10.4, <2.11.dev0`

#### 解决方案
```python
# 在 manifest.json 中放宽约束
{
  "requirements": [
    "pydantic>=2.10.4",  # 移除上限
  ]
}
```

---

### 2.3 循环依赖检测

#### 检测命令
```bash
# 使用 pipdepgraph
pip install pipdeptree
pipdeptree --warn silence --graph

# 检测循环
pip check
```

#### 示例输出
```
pydantic 2.11.3 depends on 'annotated-types>=0.6.0'
annotated-types 0.7.0 depends on 'typing-extensions>=4.9.0'
```

## 三、开发依赖管理

### 3.1 pyproject.toml 配置

```toml
[project]
name = "anti_loss_tag"
version = "1.6.8"
description = "Home Assistant integration for KT6368A BLE anti-loss tags"
requires-python = ">=3.11"
dependencies = [
    "bleak>=2.1.0,<3.0.0",
    "bleak-retry-connector>=3.8.0",
    "voluptuous>=0.13.1",
]

[project.optional-dependencies]
test = [
    "pytest>=7.4.0",
    "pytest-homeassistant-custom-component>=0.13.0",
    "pytest-cov>=4.1.0",
    "pytest-asyncio>=0.21.0",

    "ruff>=0.1.0",

    "pre-commit>=3.3.0",
]

[build-system]
requires = ["setuptools>=68.0"]
build-backend = "setuptools.build_meta"
```

### 3.3 锁定依赖版本

#### 生成 requirements.lock
```bash
# 使用 pip-tools
pip install pip-tools
pip-compile requirements.in --output-file requirements.lock

# 或使用 pip freeze
pip freeze > requirements.lock
```

#### 使用锁定文件
```bash
# 确保可重现的安装
pip install -r requirements.lock
```

## 四、依赖更新策略

### 4.1 定期检查更新

```bash
# 查看过期的包
pip list --outdated

# 使用 pip-upgrade
pip install pip-upgrade
pip-upgrade

# 或使用 pip-review
pip install pip-review
pip-review --auto
```

---

### 4.2 更新流程

#### 步骤1：更新依赖
```bash
# 更新单个包
pip install --upgrade bleak

# 更新所有包
pip list --outdated --format=json | \
  jq -r '.[] | .name' | \
  xargs -n1 pip install --upgrade
```

#### 步骤2：运行测试
```bash
# 运行所有测试
pytest tests/ -v

# 运行 linting
ruff check custom_components/
mypy custom_components/
```

#### 步骤3：验证功能
```bash
# 在 Home Assistant 中测试
python -m homeassistant --script check_config
```

#### 步骤4：提交更新
```bash
git add requirements.txt pyproject.toml
git commit -m "chore: update bleak to 2.1.2

- 修复 BlueZ start_notify 回归
- 测试通过：pytest -q
- HA 版本：2025.5.2
"
```

---

### 4.3 安全更新

#### 检查安全漏洞
```bash
# 使用 pip-audit
pip install pip-audit
pip-audit

# 使用 safety
pip install safety
safety check
```

#### 处理漏洞
```bash
# 更新受影响的包
pip install --upgrade bleak

# 或临时升级到修复版本
pip install bleak==2.1.2  # 包含安全修复
```

## 五、不同环境的依赖管理

### 5.1 开发环境

```bash
# 使用 virtualenv
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev,test]"
```

---

### 5.2 生产环境（Home Assistant）

#### 方案1：通过 HACS 自动管理
- HACS 会自动安装 manifest.json 中声明的依赖
- 确保版本约束正确

#### 方案2：手动安装
```bash
# 在 Home Assistant venv 中激活
source /srv/homeassistant/bin/activate

# 安装依赖
pip install bleak>=2.1.0
```

---

### 5.3 CI/CD 环境

#### GitHub Actions 示例
```yaml
name: Tests

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Set up Python
        uses: actions/setup-python@v4
        with:
          python-version: "3.11"
      - name: Install dependencies
        run: |
          pip install -e ".[test]"
      - name: Run tests
        run: pytest tests/ -v
      - name: Check dependencies
        run: pip check
```

## 七、故障排除

### 7.1 依赖安装失败

#### 错误：ERROR: Cannot install -requirement
```bash
# 解决：检查 Python 版本
python --version  # 需要 >=3.11

# 解决：清理缓存
pip cache purge
pip install --no-cache-dir -r requirements.txt
```

---

### 7.2 运行时导入错误

#### 错误：ModuleNotFoundError: No module named 'bleak'
```bash
# 检查安装位置
pip show bleak

# 确认 Python 路径
which python
python -c "import sys; print(sys.path)"

# 重新安装
pip install --force-reinstall bleak
```

---

### 7.3 版本冲突警告

```bash
# 检查冲突
pip check

# 输出示例：
# homeassistant 2025.5.2 has requirement voluptuous==0.13.1, 
# but you have voluptuous 0.14.0

# 解决：降级到兼容版本
pip install voluptuous==0.13.1
```

## 八、最佳实践总结

### 8.1 DO（推荐）

✅ 使用版本范围而非精确版本  
✅ 定期检查更新（每月）  
✅ 锁定开发环境依赖  
✅ 使用 pip-check 检测冲突  
✅ 在 manifest.json 中明确最低版本  
✅ 文档化测试过的依赖版本  
✅ 使用 CI 测试依赖更新  

---

### 8.2 DON'T（不推荐）

❌ 不要混合 Python 环境（系统/venv/conda）  
❌ 不要在生产环境使用 `pip install -U`  
❌ 不要忽略版本兼容性矩阵  
❌ 不要在没有测试的情况下更新依赖  
❌ 不要使用 `pip install --force-reinstall` 作为默认方案  
❌ 不要在 requirements.txt 中混合开发和生产依赖
